# Markdown Parser Architecture

This crate exposes one pull-based parser and a semantic event contract shared by direct HTML rendering and a source-backed arena AST. A block pass records containers, source fragments, and definitions. One reusable inline scanner resolves a block only when its events are requested. CommonMark, independently enabled extensions, and custom construct configurations use the same implementation. The [Pull Parser Architecture](pull-parser.md) specifies the source-backed semantic event contract and implementation of lazy inline parsing, shared HTML rendering, and incremental arena AST construction.

Extensions use their syntax names throughout configuration and implementation: `table`, `strikethrough`, `autolink_literal`, `task_list_item`, and footnote constructs. Each can be enabled independently through `Constructs`; `Options::gfm()` remains a convenient preset. See [Extension configuration](extensions.md) for examples and the configuration-name migration.

MDX is no longer supported. JavaScript expressions and import/export statements are ordinary Markdown, and angle-bracket syntax follows CommonMark HTML rules. There are no MDX presets, callback hooks, tokenizer states, or AST variants. `EventParser::new` returns the parser directly, and `to_html_with_options` returns a string: Markdown has no syntax errors. Checked event consumers, document validation and Markdown serialization retain their meaningful errors. See the [API migration](pull-parser.md#infallible-construction-and-html-conversion).

## Main paths

- `to_html` and `to_html_with_options` pull `EventParser` events through the shared `EventHtmlRenderer`. This path does not construct an AST.
- `IncrementalParser` accepts text in pieces and delivers `EventParser` events for each document-level block once appended text can no longer change it. See [Incremental input](pull-parser.md#incremental-input).
- `Document::parse` builds a source-backed arena incrementally from semantic events; `Document::events` uses the same HTML writer.
- `Document` is the only AST. Markdown serialization traverses its node IDs directly; HTML rendering traverses semantic events through `EventHtmlRenderer`. Custom renderers consume events or node IDs.
- AST helpers include stack-free traversal, `text_content`, code-fence metadata, subtree detachment/attachment, and heading lookup and section replacement. Heading anchor generation uses one map to reserve both authored and generated names and retain suffix counters. Detached nodes remain in their document arena and retain stable IDs. See [Document AST and migration](document.md).

AST edits share private arena-link operations. Moves refresh subtree context after reaching their final position. Section replacement discovers its predecessor during heading selection and splices the removed contiguous sibling range once, refreshing each detached subtree and the retained parent item's hints. Empty removal ranges do not refresh context. Section copies carry the insertion position and ascend corresponding source/destination parent links without a mapping stack, materializing source-backed values before releasing the replacement document. Preorder traversal and edit refreshes use the same subtree-bounded successor helper.

`EventParser` directly owns its compact block arena, prepared definition indexes, source/configuration references and reusable `InlineParser`. Reference specialization is selected beside block preparation; no separate workspace wrapper mediates ownership. Start and end handling, including the final separator policy, share a cold document-boundary handler. Prepared child walks use one cloneable, allocation-free iterator over the block arena's sibling links.

The parser does not produce a document-wide grammar token stream or select a compatibility backend. Block and inline syntax handlers consume source bytes directly, and HTML/autolink recognizers are small shared byte state machines.

Angle-bracket autolinks deliberately diverge from CommonMark: only the schemes in the table in `src/util/scheme.rs`, in any case, and the email form `<user@host>` form links. Each scheme has a kind that defines what must follow it: a host kind (`http`, `https`, `ftp`, `sftp`, `ssh`, `irc`, `ircs`) needs `://` and a host that is non-empty and does not start with `/`, `?` or `#`; an address kind (`mailto`, `xmpp`) needs one email address, optionally followed by a `?query`, or for `xmpp` a `/resource`, made of any bytes allowed inside `<…>`; and a phone kind (`tel`, `sms`) needs `+`, digits, `-`, `.`, `(` or `)`, with at least one digit. The same table selects GFM literal schemes, where host and address kinds form bare links and phone kinds do not, and it is the HTML renderer's safe `href` list. Its doc comment states the rule for adding schemes. GFM literal domains deliberately diverge from GitHub: `domain` in `src/inline_parser/autolink.rs` takes what follows `www.` or `://` up to the first character that cannot be in one, or the trailing punctuation that ends the literal, and accepts it only when it is a non-empty RFC 952 and RFC 1123 host name, labels of letters, digits and `-` with no `_`, no empty label and no `-` at either end, where non-ASCII characters other than punctuation and whitespace count as letters for internationalized names. An invalid domain gives no literal rather than a shorter one, so `www.a_b.c` and `www.` alone are text, and `email` applies the same rule to an email's domain, though not its local part. Other `<scheme:…>` text, such as `Option<std::io::Error>` or `<xs:element>`, is raw HTML when it is valid HTML and text otherwise. There is no option to accept other schemes. The recognizer checks the scheme while scanning, without lookahead, and the Markdown serializer writes a link as `<…>` only when that recognizer reads it back as the same link and, inside a GFM table cell, its text has no `|`, which would split the cell; other links use `[text](url)`. Autolink text is written verbatim, because autolinks do not process backslash escapes. Text escapes `<` before a letter, `!`, `/` or `?`, which could start HTML. Before any other byte, it escapes `<` only when the rest of the same text, with its other escapes applied, scans as a complete email autolink; the scan stops at the next `<`, so it stays linear. Following nodes are not consulted, so an email that only forms across text nodes, which a normalized tree does not have, is written unescaped. Text is literal, so outside link text it is also escaped where GFM would read a literal autolink, with a backslash before the scheme's colon, the dot after `www` or the email's `@`. `literal_markers` in `src/inline_parser/autolink.rs` finds them with the parser's own prefix, domain and email rules, on the text as written with its other escapes, and the run of text siblings written before it, so a literal that starts in an earlier sibling is found too. Image alt is escaped the same way, outside link text: `image_text` in `src/markdown/state.rs` writes the alt as runs from text nodes, which are escaped, and runs from links, which are not, so a link parsed from alt text still links. Literal escaping of a text node in phrasing runs after the edges are encoded, so it sees the text as written. An escaped `@` in an email autolink keeps it from forming, so the escape before its `<` is then dropped. `angle_reads_back` in `format_link_as_auto_link.rs` decides whether `<text>` reads back as a given link.

Ordinary inline regions scan physical source fragments without copying them. Constructs that span stripped container prefixes use a lazily constructed logical view and source-segment map with the same scanner. Semantic values map back to source ranges when contiguous, or materialize only the value that requires normalization. Logical-view offsets never escape in public events.

Every value stores LF for a source line ending, whether the source used LF, CRLF or a lone CR, so a CR in a value comes only from a character reference. The event parser checks once whether the source has a CR, and if so writes the line endings of each source-range value as LF as the event is yielded; the value builder does the same for source fragments it copies into an owned value, and lazily inferred reference and footnote labels are normalized the same way. Separators store LF too, and the document start reports LF as the output line ending whenever the source has a line ending, so HTML from a CRLF or CR document is byte-identical to HTML from its LF version. `IncrementalParser` tracks whether pushed text has a CR as it arrives, so preparing again does not rescan the source. Inline HTML and titles share source-backed value construction. Physical continuation indentation is removed in the same pass as optional escape/entity decoding and NUL replacement. Entity-produced line endings do not remove following whitespace. Numeric references use a stack UTF-8 buffer instead of a temporary owned string. Empty source fragments do not interrupt a contiguous semantic value; leading escapes can therefore retain the remaining source slice. Entirely empty values preserve their initial offset. The builder keeps one `Text` state and adopts existing owned buffers without copying; short initial fragments retain ordinary append-growth behavior.

HTML heading IDs and AST heading enumeration share semantic text extraction and terminal-line-ending trimming. General AST text also includes code-block values; heading text excludes them. Setext selection borrows those same semantic slices and combines its nonempty-text and literal-break checks in one early-exiting walk. The Markdown serializer uses the same one-terminal-line-ending trim rule. Source endpoint calculations for tables, HTML, definitions and frontmatter use that same terminal-ending helper.

Bare inline link destinations use the shared candidate-byte scanner to skip ordinary URL runs. Scalar handling retains escapes, balanced parentheses, whitespace and control-byte rules; NUL remains destination data until value decoding replaces it. This uses NEON on supported AArch64 targets and the existing scalar fallback elsewhere, without extra parser state or allocation.

Reference and footnote indexes normalize raw identifiers before inline resolution. They preserve authored definitions, including duplicates. Shared sort/deduplication and binary-search helpers break ties by authored position so lookup selects the first normalized identifier. Their distinct normalization policies remain at the callers. String decoding honors independently disabled escape and character-reference constructs. HTML 5 character-reference decoding is internal; the hidden `decode_named`/`decode_numeric` exports and unused HTML 4 table have been removed. Frontmatter, math, tables, tasks, literal links, and inline-code metadata have direct handlers in the block or inline parser.

Reference keys borrow contiguous canonical ASCII labels from source; other forms use owned normalized storage. Their ASCII letters use lowercase internally after Unicode folding; footnote keys retain uppercase because they appear in rendered IDs. Pending block separators are explicit delivery phases rather than independent parser state.

Unicode identifier folding shares a helper that skips the intermediate lowercase string when the label contains no non-ASCII uppercase character. Labels containing those characters retain the full string lower-then-upper conversion, including contextual casing and expansions. Exhaustive scalar and contextual tests preserve the existing matching rules.

The Markdown serializer shares destination/title formatting for definitions, links and images. Resource and reference links share label rendering while retaining their distinct following context. The serializer expects a tree normalized by `Document::normalize`, which removes empty text, joins adjacent text, and merges adjacent emphasis, strong or strikethrough of the same kind, whose sequences would otherwise join into one run: `*a*_b_` becomes `*ab*`. It does no work to cope with other trees. They are written without panicking, but may be written incorrectly or unstably. Only guards against panics remain, such as an empty text having no edge character. `Document::parse` does not normalize, since joining text across escapes or character references would copy it out of the source; `normalize_markdown` normalizes before serializing. Each attention node chooses `*` or `_` in `markdown::attention` from the characters immediately around it and the sequences it touches, in constant time, so serialization stays linear; where neither marker forms locally, the configured one is used. Attention passes its children the lengths of the marker runs it is written with and whether they can both open and close, so a child that joins its run at one edge chooses the other marker when the rule of 3 would then keep the runs at the two edges from pairing. Formatting-option checks live beside their options and run only at the original construct-specific call sites.

The Markdown serializer writes its three possible block separators directly from static strings, without an intermediate join representation or per-boundary newline allocation.

Code, math and frontmatter formatting share one byte iterator over complete marker runs. Inline delimiters choose the first absent run length; block fences choose a length above the longest run. Table escaping shares run continuation for a known backtick start and the iterator for exact matching of later runs. Keep these selection policies distinct even though the byte scanning is shared. Code/frontmatter bodies reserve space for the body, closing fence and terminating line ending together to avoid immediate growth after a large body.

Inline delimiter selection records short run lengths in one machine-word bitset and collects only longer lengths, all in one scan. Ordinary contents avoid a temporary allocation; long lengths are sorted only if the word is full. This preserves the first absent length without repeatedly scanning dense contents.

The Markdown serializer writes recursively into one output string. Output ranges provide preceding context without copying parent strings; reusable scratch handles indentation and table escaping. Cells containing no pipe stay in the output buffer without a scratch rewrite. Pipe-containing cells copy ordinary UTF-8 spans together and insert escapes only at the required pipes, retaining code-span and backslash-parity rules. Escape rules read a borrowed three-part byte view of preceding context, current input and following context. A preflight check uses the same rule predicate to skip rules that cannot affect the input or its immediately preceding escape; possible matches retain the full prefix walk to preserve non-overlapping neighbor consumption. Only those relevant escape positions are collected and sorted. This removes the assembled context string, but escape-heavy adjacent nodes can still rescan preceding context. The serializer tracks only contexts used by escape rules or nested-list marker selection. Formatting and escaping use byte scanners and static scope rules; regex is a test-only dependency. Ordered-list markers use ASCII digits.

Inline code/math normalization uses the same scratch rewrite helper as table escaping and indentation, and skips rewriting values without CR/LF. Phrasing lookahead can return a text value's first character directly when it is outside every escape rule's candidate byte. ASCII spaces/tabs, physical line endings and other context-sensitive prefixes retain speculative rendering, preserving task trimming, wrapping and diagnostic order.

List markers are written directly into the shared output. Ordered items reuse the current traversal position, making sibling numbering linear in the number of items. Serializing an attached item on its own scans its source-list siblings once to retain its original number and uses the configured ordered marker.

Image titles retain source ranges or literal values until the image closes, then use the shared escaping writer directly. Custom borrowed titles are owned before their event returns.

Footnote backreferences write through the shared HTML writer instead of assembling intermediate markup and escaped option strings. Ordered-list attributes and footnote counters format into a stack buffer without temporary strings. Each repeated backlink formats its number once and reuses it for the ID suffix and superscript; footnote bodies remain buffered until document completion.

The HTML renderer retains footnote definitions in completion order and calls in first-use order, caching each called label's escaped ID. At completion, the parser's shared indexing helpers index only called labels. One walk matches definitions in completion order and stops when every called label has a body. Duplicate definitions retain the first completed body, including an empty body. Documents without calls skip indexing, and unused labels consume no index storage. Call lookup remains linear in distinct called labels.

List-item spacing inference and Markdown formatting share a physical line-ending iterator. Spacing inference stops at the required ending or the first spread child pair, preserving source-boundary and CRLF behavior.

Authored reference syntax scans bracket candidates in reverse and counts only their immediately preceding backslashes. Each escape run is examined once; ordinary label bytes do not trigger repeated prefix scans. Email resolution reuses the first located `@` while retaining the full run as the local-part boundary.

Diagnostics use static identifiers, borrowed or owned reasons, and optional half-open byte spans. `Message::span` replaces the former boxed `Place`; public `unist` coordinates and the hidden `Location` helper have been removed. Custom producers can still return `StreamError::Parse(Message)`.

The Markdown serializer lives in `src/markdown/`. Keep its construct handlers and safety logic separate from the parser's event-to-HTML compiler. Serializer changes should preserve references, extensions, and formatting options when possible.

`MarkdownOptions::line_wrapping` controls soft source line breaks in text. `Preserve` is the default and keeps round-trip behavior; `Unwrap` joins those breaks with spaces. Unwrapping splits text at LF, the only line ending a parsed value has, and borrows the text between them, retaining scalar normalization for multiline values; a CR in a value is content and is kept; only adjacent ASCII spaces and tabs are trimmed. Explicit hard-break nodes, code, and block boundaries are not unwrapped. The serializer does not currently enforce a line width.

## Code fences

`EventKind::CodeBlock::fence` retains the opening character, length and indentation in [`CodeFence`](../src/code_fence.rs), independently of node provenance. Indented code and synthetic blocks without fence metadata use `None`. `NodeSyntax::Code` lazily exposes the decoded complete opening info string, while language and semantic body remain on the event. Frontmatter syntax retains both opening and closing fence lengths. Markdown serialization chooses ordinary code formatting from `MarkdownOptions`.

## Frontmatter

`Constructs::frontmatter` recognizes closed fences only at the beginning of a document, outside containers and without opening indentation. Every form produces an opaque leaf with `NodeSyntax::Frontmatter`: untagged `---` and `+++`, tagged delimiter forms (including `---yaml`), and language-tagged backtick or tilde fences.

The node follows Markly/cmarkly's format-agnostic model: syntax `info` is the entire opaque info string, trimmed only at its outer spaces and tabs; `Document::frontmatter_value` returns the raw body, including its trailing line ending. The first info word identifies the language, with `yaml` implied by untagged dash delimiters and `toml` by untagged plus delimiters. The authored info string is empty when the language is implicit. Callers decode the body using the appropriate language parser. Opening and closing fence lengths are retained. Opening fences, info strings and closing delimiter checks share private `CodeFence` helpers across parsing, syntax inference and serialization; indentation remains specific to each source context. Closing code fences follow the usual marker, minimum length, and indentation rules; the Rust extension requires a closing fence for every form.

HTML rendering omits frontmatter. All frontmatter uses one Markdown serialization handler, which preserves info and body while normalizing fence spacing. A parsed body's line endings are already LF. It lengthens code fences when edited content could close them, and switches conflicting dash/plus delimiters to tildes, making an implicit language explicit in the replacement fence. Edited bodies without a trailing line ending gain one before the closing fence. Keep these safety checks in the Markdown handler, separate from the public AST type.

## Tests and generated data

Integration tests are organized by Markdown construct in `tests/`; keep regressions close to the behavior they cover. `tests/commonmark.rs` exercises the CommonMark corpus, with comments marking deliberate divergences that the generator applies from its `DIVERGENCES` table, and `tests/html_renderer.rs`, `tests/markdown_renderer.rs`, and `tests/document.rs` cover document rendering and edits. `tests/markdown_serializer_*.rs` contains the Markdown serializer corpus. Its test-only declarative fixture builder converts constructor descriptions into real documents; it is not a second parser or renderer. `tests/roundtrip_fuzz.rs` round-trips generated corpora through normalizing and serializing against a checked-in baseline of failures; see [Round-trip Fuzz Harness](roundtrip-fuzz.md) for its corpora, usage and how to compare a branch with main.

Run formatting, linting, and tests from the workspace root. The standard test workflow requires 100% source-region coverage for the published `base-markdown` package across all targets and features, then runs the workspace test task. This runs the package's tests again with default features and covers the private Bake and generator packages, which are outside the coverage gate. The crate exposes optional `json` and `serde` features. The removed grammar tokenizer's tracing `log` feature is no longer accepted. The `generate/` program refreshes generated CommonMark and Unicode data used by the tests.
