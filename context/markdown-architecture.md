# Markdown Parser Architecture

This crate exposes one pull-based parser and a semantic event contract shared by direct HTML rendering and a source-backed arena AST. A block pass records containers, source fragments, and definitions. One reusable inline scanner resolves a block only when its events are requested. CommonMark, independently enabled extensions, and custom construct configurations use the same implementation. The [Pull Parser Architecture](pull-parser.md) specifies the source-backed semantic event contract and implementation of lazy inline parsing, shared HTML rendering, and incremental arena AST construction.

Extensions use their syntax names throughout configuration and implementation: `table`, `strikethrough`, `autolink_literal`, `task_list_item`, and footnote constructs. Each can be enabled independently through `Constructs`. See [Extension configuration](extensions.md) for examples and the configuration-name migration.

CommonMark is the core syntax, and each extension is documented once, on its `Constructs` field. The presets on `Constructs`, `ParseOptions`, `CompileOptions` and `Options` combine them, and the `Options` rustdoc lists what each enables and how it diverges from its namesake. `default()` enables the GFM extensions (tables, task list items, footnotes, `~~` strikethrough, literal autolinks) and frontmatter, without single-tilde strikethrough; `normalize_markdown` parses with it. `gfm()` adds single-tilde strikethrough and the tag filter and drops frontmatter, and lists its differences from GitHub. `commonmark()` enables no extensions, and only angle-bracket autolinks differ from CommonMark; the CommonMark spec suite runs with it. In every preset a `www.` literal links to `https://`.

MDX is no longer supported. JavaScript expressions and import/export statements are ordinary Markdown, and angle-bracket syntax follows CommonMark HTML rules. There are no MDX presets, callback hooks, tokenizer states, or AST variants. `EventParser::new` returns the parser directly, and `to_html_with_options` returns a string: Markdown has no syntax errors. Checked event consumers, document validation and Markdown serialization retain their meaningful errors. See the [API migration](pull-parser.md#infallible-construction-and-html-conversion).

## Main paths

- `to_html` and `to_html_with_options` pull `EventParser` events through the shared `EventHtmlRenderer`. This path does not construct an AST.
- `IncrementalParser` accepts text in pieces and delivers `EventParser` events for each document-level block once appended text can no longer change it. See [Incremental input](pull-parser.md#incremental-input).
- `Document::parse` builds a source-backed arena incrementally from semantic events; `Document::events` uses the same HTML writer.
- `Document` is the only AST. Markdown serialization traverses its node IDs directly; HTML rendering traverses semantic events through `EventHtmlRenderer`. Custom renderers consume events or node IDs.
- AST helpers include stack-free traversal, `text_content`, code-fence metadata, subtree detachment/attachment, and heading lookup and section replacement. Heading anchor generation uses one map to reserve both authored and generated names and retain suffix counters. Detached nodes remain in their document arena and retain stable IDs. See [Document AST and migration](document.md).

AST edits share private arena-link operations. Moves refresh subtree context after reaching their final position. Section replacement discovers its predecessor during heading selection and splices the removed contiguous sibling range once, refreshing each detached subtree and the retained parent item's hints. Empty removal ranges do not refresh context. Section copies carry the insertion position and ascend corresponding source/destination parent links without a mapping stack, materializing source-backed values before releasing the replacement document. Preorder traversal and edit refreshes use the same subtree-bounded successor helper.

`EventParser` directly owns its compact block arena, prepared definition indexes, source/configuration references and reusable `InlineParser`. Reference specialization is selected beside block preparation; no separate workspace wrapper mediates ownership. Start and end handling, including the final separator policy, share a cold document-boundary handler. Prepared child walks use one cloneable, allocation-free iterator over the block arena's sibling links.

The parser does not produce a document-wide grammar token stream or select a compatibility backend. Block and inline syntax handlers consume source bytes directly, and HTML/autolink recognizers are small shared byte state machines.

Angle-bracket autolinks deliberately diverge from CommonMark: only the schemes in the table in `src/util/scheme.rs`, in any case, and the email form `<user@host>` form links. Each scheme has a kind that defines what must follow it: a host kind (`http`, `https`, `ftp`, `sftp`, `ssh`, `irc`, `ircs`) needs `://` and a host that is non-empty and does not start with `/`, `?` or `#`; an address kind (`mailto`, `xmpp`) needs one email address, optionally followed by a `?query`, or for `xmpp` a `/resource`, made of any bytes allowed inside `<…>`; and a phone kind (`tel`, `sms`) needs `+`, digits, `-`, `.`, `(` or `)`, with at least one digit. The same table selects GFM literal schemes, where host and address kinds form bare links and phone kinds do not, and it is the HTML renderer's safe `href` list. Its doc comment states the rule for adding schemes. GFM literal domains deliberately diverge from GitHub: `domain` in `src/inline_parser/autolink.rs` takes what follows `www.` or `://` up to the first character that cannot be in one, or the trailing punctuation that ends the literal, and accepts it only when it is a non-empty RFC 952 and RFC 1123 host name, labels of letters, digits and `-` with no `_`, no empty label and no `-` at either end, where non-ASCII characters other than punctuation and whitespace count as letters for internationalized names. An invalid domain gives no literal rather than a shorter one, so `www.a_b.c` and `www.` alone are text, and `email` applies the same rule to an email's domain, though not its local part. Other `<scheme:…>` text, such as `Option<std::io::Error>` or `<xs:element>`, is raw HTML when it is valid HTML and text otherwise. There is no option to accept other schemes. The recognizer checks the scheme while scanning, without lookahead, and the Markdown serializer writes a link as `<…>` only when that recognizer reads it back as the same link and, inside a GFM table cell, its text has no `|`, which would split the cell; other links use `[text](url)`. Autolink text is written verbatim, because autolinks do not process backslash escapes. Text escapes `<` before a letter, `!`, `/` or `?`, which could start HTML. Before any other byte, it escapes `<` only when the rest of the same text, with its other escapes applied, scans as a complete email autolink; the scan stops at the next `<`, so it stays linear. Following nodes are not consulted, so an email that only forms across text nodes, which a normalized tree does not have, is written unescaped. Text is literal, so outside link text it is also escaped where GFM would read a literal autolink, with a backslash before the scheme's colon, the dot after `www` or the email's `@`. `literal_markers` in `src/inline_parser/autolink.rs` finds them with the parser's own prefix, domain and email rules, on the text as written with its other escapes, and the run of text siblings written before it, so a literal that starts in an earlier sibling is found too. What follows a text node in phrasing starts with punctuation, which ends a domain or, as the `_` of attention, makes it invalid, so a literal never runs on into the next node. An escape added before an email's `@` ends a `www.` or scheme literal before it, so a literal whose domain was invalid only because of trailing punctuation before that `@` is checked again without it. Image text is written as phrasing, like link text, under its own construct, `ConstructName::ImageLabel`, so every child the parser gives it reads back as itself: footnote calls, links, references, autolinks and images in it are written as they are, and its nodes count toward the nesting limit (#190). Unlike link text, literals form in image text unless the image is inside link text, so text there is escaped as outside link text, and a literal link there is written bare where it would be in a paragraph; `alt_start` in `src/markdown/state.rs` lets one at the start of the text count `![` as the boundary before it. Image text keeps spaces and tabs at its end, written raw before `]`, so a literal before them is at a boundary too, where at the end of a paragraph they would be written as references. Image text that starts with `^` is written with `\^`, since `![^` starts no image. An escape found in the text written before a node, which `write_safe` sees as context, is not the escape it was asked for, so a `(` after a shortcut reference such as `![[r]\(x)](u)` is still escaped. Literal escaping of a text node in phrasing runs after the edges are encoded, so it sees the text as written. An escaped `@` in an email autolink keeps it from forming, so the escape before its `<` is then dropped. `angle_reads_back` in `format_link_as_auto_link.rs` decides whether `<text>` reads back as a given link.

Ordinary inline regions scan physical source fragments without copying them. Constructs that span stripped container prefixes use a lazily constructed logical view and source-segment map with the same scanner. Semantic values map back to source ranges when contiguous, or materialize only the value that requires normalization. Logical-view offsets never escape in public events.

Every value stores LF for a source line ending, whether the source used LF, CRLF or a lone CR, so a CR in a value comes only from a character reference. The event parser checks once whether the source has a CR or NUL, and if so writes the line endings of each source-range value as LF, and each NUL as U+FFFD, as the event is yielded; `Text::normalized` in `stream.rs` does both, calling `push_normalized` in `util::line_ending`, and the value builder does the same for source fragments it copies into an owned value, and lazily inferred reference and footnote labels are normalized the same way. Separators store LF too, and the document start reports LF as the output line ending whenever the source has a line ending, so HTML from a CRLF or CR document is byte-identical to HTML from its LF version. `IncrementalParser` tracks whether pushed text has a CR or NUL as it arrives, so preparing again does not rescan the source. Inline HTML and titles share source-backed value construction. Physical continuation indentation is removed in the same pass as optional escape/entity decoding. No value holds NUL, so validation rejects it, and the raw values, inline code, code blocks, HTML and frontmatter, hold no CR. Entity-produced line endings do not remove following whitespace. Numeric references use a stack UTF-8 buffer instead of a temporary owned string. Empty source fragments do not interrupt a contiguous semantic value; leading escapes can therefore retain the remaining source slice. Entirely empty values preserve their initial offset. The builder keeps one `Text` state and adopts existing owned buffers without copying; short initial fragments retain ordinary append-growth behavior.

HTML heading IDs and AST heading enumeration share semantic text extraction and terminal-line-ending trimming. General AST text also includes code-block values; heading text excludes them. Setext selection borrows those same semantic slices and combines its nonempty-text and literal-break checks in one early-exiting walk. The Markdown serializer uses the same one-terminal-line-ending trim rule. Source endpoint calculations for tables, HTML, definitions and frontmatter use that same terminal-ending helper.

Bare inline link destinations use the shared candidate-byte scanner to skip ordinary URL runs. Scalar handling retains escapes, balanced parentheses, whitespace and control-byte rules; NUL remains destination data until the event is yielded, which replaces it. This uses NEON on supported AArch64 targets and the existing scalar fallback elsewhere, without extra parser state or allocation.

Reference and footnote indexes normalize raw identifiers before inline resolution. They preserve authored definitions, including duplicates. Shared sort/deduplication and binary-search helpers break ties by authored position so lookup selects the first normalized identifier. Their distinct normalization policies remain at the callers. String decoding honors independently disabled escape and character-reference constructs. HTML 5 character-reference decoding is internal; the hidden `decode_named`/`decode_numeric` exports and unused HTML 4 table have been removed. Frontmatter, tables, tasks, literal links, and inline-code metadata have direct handlers in the block or inline parser.

A reference's label, and a footnote's, is carried by its event: `Tag::Link` and `Tag::Image` hold a `Target`: a `Resource` with its destination and title, a `Reference` by name, its kind and label, as a document stores it, or a `Resolved` reference, the name with its definition's destination and title, as the event stream carries it, and `Tag::FootnoteDefinition` and `EventKind::FootnoteReference` have the normalized `identifier` and the `label`, both as the parser read them (#192). The inline parser records the range of each label it read in its logical text, without the prefixes of the lines it continues on in a container, such as a block quote's `>` or an item's indentation, and yields it as a value, which is the source range when it is contiguous; a footnote definition's label comes from `footnote_prefix` in the block parser. So `Document::parse`, `AstBuilder` over `EventParser` or `IncrementalParser`, and deserialization build the same document, and nothing is inferred from a node's span. A label is written as authored, inside the prefixes its container writes again (#146). A bound reference copied into another document by `Document::replace_heading_section` becomes a resource to where it led, and an unbound one, or an unbound footnote call, the text it rendered as.

Reference keys borrow contiguous canonical ASCII labels from source; other forms use owned normalized storage. Their ASCII letters use lowercase internally after Unicode folding; footnote keys retain uppercase because they appear in rendered IDs. Pending block separators are explicit delivery phases rather than independent parser state.

Unicode identifier folding shares a helper that skips the intermediate lowercase string when the label contains no non-ASCII uppercase character. Labels containing those characters retain the full string lower-then-upper conversion, including contextual casing and expansions. Exhaustive scalar and contextual tests preserve the existing matching rules.

The Markdown serializer shares destination/title formatting for definitions, links and images. It finds the root of the tree it writes in once, at the first reference, and looks references up there, in the document's index of its definitions when that is the attached document, and in those of the written subtree, through a table of it built in one pass, when that is not a whole tree, so writing a deep subtree, or each section in turn, stays linear: a reference is written as one when the definition it is bound to is the first of its label in what is written, which it then reads back bound to, and otherwise as a resource to where it leads; an unbound one, which a normalized tree has none of, is written as a reference, which reads back as text. Literal `[` in phrasing is always escaped, so text such as `*[foo*]` reads back as text whatever definitions are written with it. Resource and reference links share label rendering while retaining their distinct following context. The serializer expects a tree normalized by `Document::normalize`, which removes empty text, joins adjacent text, and merges adjacent emphasis, strong or strikethrough of the same kind, whose sequences would otherwise join into one run: `*a*_b_` becomes `*ab*`. It also joins adjacent inline code, moves whitespace out of the edges of emphasis, strong and strikethrough into sibling text, and removes soft breaks at the edges of paragraphs, headings and table cells, hard breaks at their end, paragraphs left empty, inline HTML and inline code without a value, and lists without items, which no Markdown writes, so the serializer never writes whitespace inside a marker, a code span against another, or a break it cannot express. Normalizing fixes only the shape of the tree: values are raw characters, and it never changes them, as a value is valid only in the form the parser stores it, except that it gives a code block value that does not end the document the final line ending it cannot be written without. Encoding is the serializer's work: it writes any characters in text so that they read back, with backslash escapes or character references, including the spaces and tabs at the edges of a paragraph, heading or table cell that the parser would trim, such as `&#x20;hi&#x20;` for the text `  hi  `. It does no work to cope with other trees. They are written without panicking, but may be written incorrectly or unstably. Only guards against panics remain, such as an empty text having no edge character. `Document::parse` does not normalize, since joining text across escapes or character references would copy it out of the source; `normalize_markdown` normalizes before serializing. Attention is planned in `markdown::attention` for each paragraph, heading, table cell and link text at a time, under three rules: each node is written with its own runs, which use another marker than the runs next to them, but for a first child that writes its opening sequence in its parent's opening run and a last child that writes its closing sequence in its parent's closing run, both of the parent's marker; every literal `*`, `_` and `~` is escaped; and runs nest as the nodes do. What is left is local: whether each run opens and closes, whether a run that can open and close closes an earlier open run of its marker, and whether a closing run pairs with its opening run by the rule of 3, which for a shared run counts the whole run. The planner is dynamic programming over the tree of the scope's pieces. A list of pieces is planned left to right with a state for the kind of the last character written and the kind the next must be; each attention node is planned once for each context it can be in, the open runs around it as a set of markers and sizes modulo 3 and the shared run its parent writes it in, if any, and gives the least cost of each way to write it by the kinds of character before it and after its closing run. A shared opening run passes its size modulo 3 down the chain of first children, which the innermost checks; a shared closing run passes the sizes and the sizes it pairs with up the chain of last children, which the outermost checks. It chooses each node's sequence, which runs are shared, and which letters at the edges of text are written as character references, preferring fewer references, then fewer shared runs, then the configured markers, first checking in one pass the plan that writes the configured markers, or in a scope of up to eight attention nodes the plans that change one of them, which most writing has, and otherwise trying other sequences, then shared runs, then references, and stopping at the first that writes the scope. Contexts are bounded, and keep only the open runs that a run inside can close, so the work is linear in the size of the scope, though with a large constant for nested attention: a chain of attention twelve deep, each level sharing its parent's opening run, takes about 350 µs to plan, where the old writer took 6 µs. Where no choice works, the writer returns `unwritable-node`. The plan takes the characters next to every run from the writer: each text, soft break and hard break is written for the plan by the function that writes it (`State::write_leaf`), with the edits its next sibling makes to its end, after what the children before it are written as, links and images give the edge characters of the form the writer chooses for them (`State::link_ends`), other nodes are written by their own functions, and the plan reads the kinds of their first and last characters; a next sibling whose first character depends on what is before it is written after the child, as the writer writes both, to see it, and everything written on trial, with the state it sets, is then removed, so the line starts where whitespace is written as a reference and the line endings that unwrapping writes as spaces are judged as written; `State::check_runs` checks the runs against the parser's pairing in debug builds. The parser and the planner share the flanking and rule-of-3 predicates in `util::attention`. Formatting-option checks live beside their options and run only at the original construct-specific call sites.

The serializer writes for the document's dialect, `Document::parse_options` (#257), which `to_markdown_node` copies into `State::parse`. Every decision that depends on what the parser reads, an escape, a hazard such as a line that would start a block, a definition or a table, or the form of a construct, asks the block parser's predicates with those options (`continuation_starts_block`, `starts_definition`, `definition_has_title`, `html_interrupts_paragraph`, `complete_tag_starts_html_block`, `html_block_keeps_line_ending`) or reads `State::parse` directly. Where the options turn a construct off, the handler writes another that reads back the same: `heading_as_setext` writes setext without ATX headings, `hard_break` trailing spaces without the escape, `format_code_as_indented` indents without fences, and `written_link` falls back to an autolink where links with text are off. Under `ParseOptions::html_block_blank_lines`, an HTML block of kind 6 or 7 can keep its final line ending and the blank lines after it; it is written without the final one, and `ends_in_kept_line_ending` makes the separator after it, and the line ending at the end of the output, give it back. Labels keep the shape `normalize` gives them under the default options, which read every block start, so they read back under any options. Where no spelling reads back, a handler calls `State::no_spelling` or `State::no_spelling_of`, which records the first such node, and `to_markdown_node` returns `unwritable-node` for it once the output is written. Characters are written through `State::literal`, a `Literal` of whether the options read backslash escapes and character references; where they read neither, a character is written as it is, which `raw_literal` records: in a paragraph, heading or table cell, `State::verifying` holds, and `check_block` reads the written block back with its container prefixes and compares its inline events, as it does for a literal autolink written next to what may change where it ends (`WrittenLink::Loose`). Without backslash escapes, the escape table's rules apply only where the options read the construct the character would start (`Rule::need`), so that no character is encoded that needs none; with them, every rule applies, so the output reads the same under other options. Without fences, `next_bullets` plans the bullets of a run of adjacent lists from the last back, so that each list leaves the next one a bullet. `tests/dialect_round_trip.rs` checks that random documents under random options round trip or return `unwritable-node`, and reports how many do.

References and the lines around them follow a few local rules so they read back (#146). A shortcut reference followed by a node that starts with `[` is written collapsed, `[r][]`, since `[r][s]` would read as one full reference. The `:` after a reference that starts a paragraph, or a footnote reference that starts a line, is escaped whatever node writes it. Once a paragraph is written, with its container prefixes, `escape_delimiter_rows` in `src/markdown/state.rs` escapes the first character of any line that would read as a GFM delimiter row under the line before it, using `starts_table` from the block parser, and `separate_html_start` encodes the line ending after a complete tag alone on a paragraph's first line, which would otherwise start an HTML block. Labels of references, definitions and footnotes are written verbatim by `write_label`, so every label must be one the parser can produce, and one shared predicate, `valid_label` in `src/node_syntax.rs`, rejects any other with `StreamError::InvalidValue` where it is assigned: it needs something other than whitespace, no carriage return, no blank line, no unescaped bracket, and no trailing lone backslash. Validity does not depend on `ParseOptions`: it accepts every label the parser produces under any options, so a continuation line such as `# b`, which a parser with headings off reads as part of a label, is valid, and assignment never fails on parsed input. Whether a label reads back under the default options is `normalize`'s job (below), not the assignment check's. A full reference's, a definition's and a footnote's label must also fit the parser's 999 characters, a tab counting the columns it spans at the column that suits each line best and line endings and the indentation after them not counting (`label_fits`); a footnote definition's label holds no whitespace, and a footnote identifier must be `normalize_identifier` of its label, or of itself without one. The parser reads a shortcut or collapsed reference's label, which is the link's text, at any size, so it is not limited; when such a label is too long for a full reference and the link's text no longer matches it, the serializer writes the link as a resource. Since the label's columns depend on where it is written, `Document::normalize` gives labels a shape that reads back anywhere under the default options (`normalized_label`, `label_fits_anywhere`): a continuation line that would start a block, which it asks the block parser itself (`continuation_starts_block`, its interruption rules plus a setext underline; any list item interrupts a definition), or could be a table delimiter row under whatever line comes before it (`block_parser::delimiter_row`, whatever the head; four columns of indentation make it indented code, which cannot interrupt a paragraph in any container), or whose leading tabs are column-dependent, has its leading whitespace replaced by four spaces, other tabs in a label too long at the worst column become one space, a link or image still too long becomes a resource and a footnote call still too long loses its label, and in ATX headings and table cells, which hold no line ending, whitespace runs with one become a space. When a container consumes only part of a tab before a label's continuation line, the parser keeps the remaining columns as spaces at the start of that line of the label (`LineStart::remaining_space`, carried through paragraph and definition fragments), so the label written back with its container prefix reads the same. A heading of rank 1 or 2 whose reference or footnote label holds a line ending is written setext.

The Markdown serializer writes its three possible block separators directly from static strings, without an intermediate join representation or per-boundary newline allocation.

Code formatting shares one byte iterator over complete marker runs. Inline delimiters choose the first absent run length; block fences choose a length above the longest run. Table escaping shares run continuation for a known backtick start and the iterator for exact matching of later runs. Keep these selection policies distinct even though the byte scanning is shared. Code and frontmatter bodies reserve space for the body, closing fence and terminating line ending together to avoid immediate growth after a large body.

Inline delimiter selection records short run lengths in one machine-word bitset and collects only longer lengths, all in one scan. Ordinary contents avoid a temporary allocation; long lengths are sorted only if the word is full. This preserves the first absent length without repeatedly scanning dense contents.

The Markdown serializer writes recursively into one output string. Output ranges provide preceding context without copying parent strings; reusable scratch handles indentation and table escaping. Cells containing no pipe stay in the output buffer without a scratch rewrite. Pipe-containing cells copy ordinary UTF-8 spans together and insert escapes only at the required pipes, retaining code-span and backslash-parity rules. Escape rules read a borrowed three-part byte view of preceding context, current input and following context. A preflight check uses the same rule predicate to skip rules that cannot affect the input or its immediately preceding escape; possible matches retain the full prefix walk to preserve non-overlapping neighbor consumption. Only those relevant escape positions are collected and sorted. This removes the assembled context string, but escape-heavy adjacent nodes can still rescan preceding context. The serializer tracks only contexts used by escape rules or nested-list marker selection. Formatting and escaping use byte scanners and static scope rules; regex is a test-only dependency. Ordered-list markers use ASCII digits.

Inline code holds no line ending, so the writer writes its value as it is, escaping only pipes in table cells. Phrasing lookahead can return a text value's first character directly when it is outside every escape rule's candidate byte. ASCII spaces/tabs, physical line endings and other context-sensitive prefixes retain speculative rendering, preserving task trimming, wrapping and diagnostic order.

List markers are written directly into the shared output. Ordered items reuse the current traversal position, making sibling numbering linear in the number of items. Serializing an attached item on its own scans its source-list siblings once to retain its original number and uses the configured ordered marker.

Image titles retain source ranges or literal values until the image closes, then use the shared escaping writer directly. Custom borrowed titles are owned before their event returns.

Footnote backreferences write through the shared HTML writer instead of assembling intermediate markup and escaped option strings. Ordered-list attributes and footnote counters format into a stack buffer without temporary strings. Each repeated backlink formats its number once and reuses it for the ID suffix and superscript; footnote bodies remain buffered until document completion.

The HTML renderer retains footnote definitions in completion order and calls in first-use order, caching each called label's escaped ID. At completion, the parser's shared indexing helpers index only called labels. One walk matches definitions in completion order and stops when every called label has a body. Duplicate definitions retain the first completed body, including an empty body. Documents without calls skip indexing, and unused labels consume no index storage. Call lookup remains linear in distinct called labels.

List-item spacing inference and Markdown formatting share a physical line-ending iterator. Spacing inference stops at the required ending or the first spread child pair, preserving source-boundary and CRLF behavior. A nested list or footnote definition takes the blank lines after its last block into its span, so for a pair whose first child is a list, item, footnote definition or block quote, inference also looks through the last children of lists, items and footnote definitions for a blank line at their end, as CommonMark does and as the parser does when it makes the list loose; a block quote's own lines of `>` alone do not count. The serializer writes an item spread whenever it writes a blank line between two of its blocks, as that blank line reads back as spread. With `tight_definitions`, adjacent definitions are joined by a line ending even in a spread item, and every other join is the one written without it; in a spread item whose only blocks are definitions, they are joined by blank lines, as nothing else would show its spread.

Authored reference syntax scans bracket candidates in reverse and counts only their immediately preceding backslashes. Each escape run is examined once; ordinary label bytes do not trigger repeated prefix scans. Email resolution reuses the first located `@` while retaining the full run as the local-part boundary.

Diagnostics use static identifiers, borrowed or owned reasons, and optional half-open byte spans. `Message::span` replaces the former boxed `Place`; public `unist` coordinates and the hidden `Location` helper have been removed. Custom producers can still return `StreamError::Parse(Message)`.

The Markdown serializer lives in `src/markdown/`. Keep its construct handlers and safety logic separate from the parser's event-to-HTML compiler. Serializer changes should preserve references, extensions, and formatting options when possible.

`MarkdownOptions::line_wrapping` controls soft source line breaks in text. `Preserve` is the default and keeps round-trip behavior; `Unwrap` joins those breaks with spaces. Unwrapping splits text at LF, the only line ending a parsed value has, and borrows the text between them, retaining scalar normalization for multiline values; a CR in a value is content and is kept; only adjacent ASCII spaces and tabs are trimmed. Explicit hard-break nodes, code, and block boundaries are not unwrapped. The serializer does not currently enforce a line width.

## Code fences

`EventKind::CodeBlock::fence` retains the opening character, length and indentation in [`CodeFence`](../src/code_fence.rs), independently of node provenance. Indented code and synthetic blocks without fence metadata use `None`. `EventKind::CodeBlock::info` is the whole opening info string, as in cmark and cmarkly (`as.code.info`): the parser trims it of the spaces and tabs at its edges and decodes it once, with backslash escapes and character references only when those constructs are on, so the stored value does not depend on options the document does not keep (#188). The language is derived from it by `stream::code_language`: the first word, up to the first space, tab or line ending of the decoded string (cmark also splits at a form feed or vertical tab; this does not), so `&#x20;` separates words like a space; an info string that starts with one has no language. The HTML renderer writes `class="language-…"` from it. The serializer writes the info string in one escape context, `CodeFencedInfo{GraveAccent,Tilde}`, encoding the spaces and tabs at its edges, line endings, backticks in a backtick fence, a `~` at its start in a tilde fence, and the escapes and references that would decode, so it reads back exactly with escapes and references on, including the spacing between words. Code with an info string is always fenced. Frontmatter syntax retains both opening and closing fence lengths. Markdown serialization chooses ordinary code formatting from `MarkdownOptions`.

## Frontmatter

`Constructs::frontmatter` recognizes closed fences only at the beginning of a document, outside containers and without opening indentation. It opens with exactly `---` or `+++`, optionally followed by a format hint (`--- json`, `---yaml`), and closes with the same three characters on a line of its own, optionally followed by spaces or tabs. Every form is stored on the root, as the body in `Tag::Document { frontmatter }` and the fences and info in the root's `NodeSyntax::Frontmatter`; it is not a node. A backtick or tilde code fence is never frontmatter, even at the start of a document.

The node follows Markly/cmarkly's format-agnostic model: syntax `info` is the entire opaque info string, trimmed only at its outer spaces and tabs; `Document::frontmatter` returns the raw body, including its trailing line ending. The first info word identifies the language, with `yaml` implied by untagged dash delimiters and `toml` by untagged plus delimiters. The authored info string is empty when the language is implicit. Callers decode the body using the appropriate language parser. Opening and closing fence lengths are retained, and are always 3 for a parsed node. Opening and closing delimiter checks share private `CodeFence` helpers across parsing and syntax inference. The Rust extension requires a closing fence.

HTML rendering omits frontmatter. All frontmatter uses one Markdown serialization handler, which preserves info and body while normalizing fence spacing. A body's line endings are LF, and one that is not empty ends in one, as validation requires. It always writes `---` or `+++`: a body with a line that would close the fence switches to the other delimiter, making an implicit language explicit, and a body that would close both is an error. Syntax with another fence character, such as a backtick or tilde code fence, which only a hand-built node can have, is written as `---` followed by its info as the language hint; with empty info that is plain `---`, which implies YAML. The closing-line check splits the body on LF, and the body is written unchanged. Keep these safety checks in the Markdown handler, separate from the public AST type.

## Tests and generated data

Integration tests are organized by Markdown construct in `tests/`; keep regressions close to the behavior they cover. `tests/commonmark.rs` exercises the CommonMark corpus, with comments marking deliberate divergences that the generator applies from its `DIVERGENCES` table, and `tests/html_renderer.rs`, `tests/markdown_renderer.rs`, and `tests/document.rs` cover document rendering and edits. `tests/markdown_serializer_*.rs` contains the Markdown serializer corpus. Its test-only declarative fixture builder converts constructor descriptions into real documents; it is not a second parser or renderer. `tests/roundtrip_fuzz.rs` round-trips generated corpora through normalizing and serializing against a checked-in baseline of failures; see [Round-trip Fuzz Harness](roundtrip-fuzz.md) for its corpora, usage and how to compare a branch with main.

Run formatting, linting, and tests from the workspace root. The standard test workflow requires 100% source-region coverage for the published `base-markdown` package across all targets and features, then runs the workspace test task. This runs the package's tests again with default features and covers the private Bake and generator packages, which are outside the coverage gate. The crate exposes optional `json` and `serde` features. The removed grammar tokenizer's tracing `log` feature is no longer accepted. The `generate/` program refreshes generated CommonMark and Unicode data used by the tests.
