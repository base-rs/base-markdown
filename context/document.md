# Document AST and migration

`Document<S>` is the single source-backed arena AST, constructed incrementally from semantic events and rendered through the same HTML writer as direct parsing. `S: AsRef<str>` can own or borrow a complete UTF-8 buffer. Ordinary text and attributes retain offsets; decoded constants and constructed values use literal or owned storage.

## Migrating from mdast

The legacy recursive AST, its compiler and separate HTML renderer have been removed. This deliberately changes the public API and serialized AST representation.

| Previous API | Document API |
| --- | --- |
| `to_mdast(source, options)` | `Document::parse(source, options)` |
| `Node` enum and child vectors | `DocumentNode::kind`, `NodeId`, `Document::children(id)` |
| `walk` | `Document::descendants(id)`, including the starting node |
| `text_content()` | `Document::text_content(id)` |
| `HtmlRenderer` and `render_with` | `Document::render_html`, `render_node`, or `render_events(document.source(), document.events(), ...)` |
| Custom `Renderer` | A consumer of semantic events, or a traversal of document node IDs |
| `Node::to_markdown`, `MarkdownRenderer` | `to_markdown(&document)`, `to_markdown_with_options`, or `to_markdown_node` |
| `Headings::extract` | `Document::headings(&HeadingOptions)` |
| `extract_children` / `Fragment` | `Document::extract_children(parent)` returns detached IDs in the same arena |
| Child-vector mutation | `append_child`, `detach`, and `attach(parent, child, before)` |
| `replace_heading_section` | `Document::replace_heading_section(parent, index, &replacement, replace_heading, remove_subsections)` |
| Code-fence helpers | `EventKind::CodeBlock::fence` and `NodeSyntax::Frontmatter` |

Events and AST nodes express resolved Markdown meaning. A reference is a name and a definition a binding of it: a document stores a reference link or image as `Target::Reference`, its kind and label, with no destination, and it leads where the first link reference definition of its label in document order does, as the parser matches labels; a footnote call likewise calls the first footnote definition with its identifier to end, which is the first in document order unless one is nested in another of its identifier, as the HTML renderer shows that one. Nothing stores a binding on a reference. A document keeps an index (`bindings::Index`) of every definition and footnote definition of the attached document by key, built from the definitions `AstBuilder` met, in the order they end, and on deserialization, and kept by every edit that attaches, detaches or relabels one (`set_kind`, `append_child`, `attach`, `detach`, `extract_children`, `replace_heading_section`); it files each entry by a hash of its key, the canonical label or identifier, in groups of a few slots, with the keys in one string it owns, so it borrows nothing, and a key whose group is full goes to an overflow ordered by key, so filing or finding a key takes constant time usually and at most time logarithmic in the number of keys whatever the keys are: the hash has no random seed, which this `no_std` crate has no source of, so keys can be made to collide, and the bound rests on the overflow. An entry holds its binding first and the copies of it, the later definitions of the key, in order after it. Parsing, building and deserializing accept copies, as Markdown does, but no edit adds one: appending, attaching, relabelling or copying in a definition of a key the attached document already defines, a subtree that defines a key twice, or moving within the document a definition whose key has copies, is rejected with `StreamError::InvalidValue` before anything changes. Detaching a definition removes it from the index, so the only definition of a key can be detached and attached again, while a copy, once detached, cannot. So the order of a key's definitions never changes while they are attached, and removing the binding makes the next copy the binding with no comparison of positions. A lookup takes that time whatever copies there are, as an entry keeps its copies in a queue that gives up its first in constant time. `Document::definition`, `footnote_definition` and `destination` and the per-subtree operations (`subtree_events`, `text_content`, `render_node`, `to_markdown_node`) look the attached document up in the index, so each reference costs one lookup there whatever the node's depth, as the document keeps one bit per node saying whether it is attached (set when the document is built or normalized and flipped only for subtrees that move into or out of the attached document, so detaching nested containers one by one costs each its own blocks), and calling one per section takes time linear in what each covers; they look a detached tree up through a table of it (`bindings::Table`), built in one pass over its containers of blocks, which are all that can hold a definition, so a call on a node in a detached tree takes time linear in that tree, and calling one on each node of a large detached tree takes quadratic time, a known gap (#226), as caching the table would need interior mutability. `Document::bindings` builds such a table of the attached document. `normalize` removes each copy, as copies render nothing, and gives each place a copy leaves, or a definition hoisted out of one fills, the separators the parser puts there between the blocks then beside it, and the end of the document the ones it puts there once normalizing is done, so the output reads back as the tree, unless those already there could not be the parser's, as an edit leaves them, and it pins the spread of each item above a copy, which is otherwise read from the source between the item's blocks, where the copy's lines would count as blank, so a normalized tree defines each key once; a definition in a footnote definition that is a copy, which binds its own key, takes the copy's place, with what it holds, and the copies in that go in turn. It does so in one pass from the root in document order that rebuilds each child list that holds a copy, or that a definition leaves, once, so the result depends on the tree alone and takes time linear in the copies, the containers above them and their children, and what the copies hold, with scratch marks cleared only where they were set, so normalizing many trees that hold copies costs what they hold, not the arena once per tree. Each copy removed is then a detached tree of its own, which the same call normalizes before going on, whatever its index, with every reference in it looked up again, as the definitions that bound them may be in the tree it left, so `normalize` leaves no tree unnormalized and its settled state is true. The root of a tree is never a copy, as its definitions are taken in the order they end but for the root, which comes first: a footnote definition detached from a copy of itself, or left a detached root when a copy around it goes, stays what it is and loses the copy it holds. The HTML changes in five cases. Removing copies that leave the only item of a loose list with fewer than two blocks makes the list tight, as a list that cannot be written loose is. And the renderer counts the footnote calls in a footnote definition that is a copy, numbering footnotes by their first call in document order, though it shows nothing of the copy, so once one is removed, footnote numbering, anchors and entries follow only the visible calls (#225): the numbers of calls, the ids of their anchors and the order of entries can change, back references to calls that are not in the output go, and so does the entry of a footnote called only there. And an item whose only block is a copy is empty once the copy goes, and an empty item cannot start a list directly after a paragraph in an item of a tight list, as `- p\n  -` reads back as a heading, so `normalize` removes it as it removes such an item whatever left it empty. And removing a copy, or hoisting a definition out of one, can leave two blocks in a row in an item of a tight list that can be written apart only with a blank line, such as two paragraphs, which `normalize` then joins, or a definition after a paragraph, which makes the list loose, as for any such pair. And where a copy after a list, or at the end of the document, goes, or a definition hoisted out of one lands, the list is written next to what then follows it, or at the end of the output, where the parser may put a line ending the tree did not have, or none where it had one, so the HTML gains or loses that line ending: `- [c]: /6\n\n[c]: /6\n` renders `<ul>\n<li></li>\n</ul>`, and normalized, `- [c]: /6\n`, which renders a line ending after it. A paragraph that a rule makes loose is likewise given the separator the parser puts after one, and a table that ends an item or footnote definition the one that a blank line after it in the item gives, which can change too when a rule makes the list loose or tight. `DocumentEvents` makes its lookup at the first reference or footnote call it meets, and gives each bound reference as `Target::Resolved`, with its definition's destination and title, so a parsed document's events, and its HTML, are the parser's; it handles references and footnote calls on a cold path, so other nodes take the path they took before. A document also records whether every reference and footnote call in it is known to be bound, which a parsed document is, as the parser gives a name only when a definition binds it, a built one is when its stream gave each reference resolved and bound and each footnote call its definition, and normalizing makes it; any edit of the tree clears it, and while it holds, `normalize` and `is_normalized` look nothing up for references. A stream carries resolved targets only: `render_events` rejects a `Target::Reference` with `StreamError::InvalidValue`. It renders footnote calls from the stream alone, so one without its definition fails with `StreamError::Unbalanced`, while `AstBuilder` keeps such a call, which the document then renders as its text. The parser's event stream carries `Target::Resolved` too; `AstBuilder` keeps its name only when its label binds to a definition with the same destination and title in the built document, and otherwise stores a resource to them, so that a resolved reference never loses its meaning, and `set_kind` and `append_child` store one as a resource, while deserialization rejects one with `StreamError::InvalidValue`. A reference or footnote call that no definition binds is valid but not normalized: `DocumentEvents` gives it as the text it reads back as, so rendering, `text_content`, `headings` and heading ids agree, and `normalize` makes it that text, as `replace_heading_section` makes one it copies. A detached subtree is its own tree, which binds only its own references. Being normalized is therefore a property of the whole document: removing or relabelling a definition can leave references elsewhere unbound. Images contain semantic alternative-text children. Tables have explicit head/body containers and per-cell alignment. A task item's checkbox is `Item { checked }`, and frontmatter is the root's `Tag::Document { frontmatter }`, so neither is a node. Soft breaks and output separators are explicit leaves. Parsed text forms one node per source slice: it is split only at backslash escapes and character references, whose values are not a slice of the source. `Document::normalize` joins adjacent text, removes empty text, merges adjacent emphasis, strong or strikethrough of the same kind, unwraps a link inside a link unless it is an autolink, and gives a table the parser's shape, in linear time; `Document::is_normalized` reports whether it would change anything. Normalize a parsed or edited tree before serializing it to Markdown. Direct-child indices, including the section helper's heading index, include separator nodes. Use IDs or filtered child traversal when source whitespace should not affect selection.

Source spans are half-open byte ranges, rather than legacy unist positions. Parsed ATX and setext heading spans include the terminating source line ending when present: use `node.span.end` directly to locate the heading body, without skipping another CR/LF. Frontmatter spans end at the closing fence before its terminating line ending. Value ranges identify semantic text and can differ from the enclosing node span; use `Text::resolve` and `Document::frontmatter` instead of slicing node spans for decoded values. Use `Document::destination` or `Bindings::destination` for where a reference leads, rather than searching definitions again: they honor first-definition precedence and the parser's label matching.

Markdown serialization preserves supported Markdown structure rather than every possible valid tree. For example, Markdown tables require a header: normalizing a table without its head makes its first row the header, and gives every row as many cells as the widest. Use HTML rendering to preserve such custom table structure.

## Ownership and editing

Node IDs are scoped to their document. Arena slots remain stable across edits and are not reclaimed on detachment. A detached subtree can be inspected, rendered, serialized or reattached. The arena holds parent/first-child/next-sibling links; traversal needs neither a heap stack nor cloned strings. Normalizing invalidates the IDs of the text and attention it joins into a preceding node; other IDs stay valid. Appending in document order, each node after the subtree before it is complete, takes amortized constant time per child: the last node appended leads to the parent's last child, and a list item's ending is refreshed from the appended child alone. Appending elsewhere scans the parent's children; inserting or moving children may scan sibling chains; editing avoids permanently enlarging every node with editing-only links or indices.

`text_mut` detaches a source-backed value on its first edit. `set_kind` changes semantic content while retaining provenance and structure, and clears authored-syntax inference for that node. Checked edits reject malformed values, cycles and invalid roots.

## Content model

A tree is either valid or not built: one content model in `stream.rs`, `TagKind::holds`, decides which children each container holds, and every path that adds nodes checks it against the parent alone: `AstBuilder`, `EventHtmlRenderer`, `append_child`, `attach`, `replace_heading_section` and serde validation. The document root, block quotes, items and footnote definitions hold blocks and separators; paragraphs, headings, table cells, attention, links and images hold phrasing; a list holds items; a table holds heads and bodies, and they hold rows, with separators between them; a row holds cells. A root whose first child is phrasing holds only phrasing, an inline document, and one whose first child is a block holds no phrasing, so the two never share a parent. The one rule on ancestors is that a footnote reference cannot be inside a link, which `attach` checks by scanning the moved subtree. A violation is `StreamError::InvalidNesting`; a heading level outside one through six is `StreamError::InvalidValue`. `render_node` renders a subtree in fragment mode, so its root's children need not fit a document.

`set_kind` changes a node in place only where its children and its place stay valid without a check: a container keeps its kind, except that emphasis, strong and strikethrough are interchangeable, and a leaf keeps its variant, with HTML staying a block or inline. Any other change creates a node, moves the children with `attach` and detaches the old one. Detaching or moving a subtree out always leaves a valid tree, if not a normalized one.

Validity is what can be built; being normalized is what is written exactly. Shapes that every tree passes through while being built, such as empty containers, rows of different widths, a table without a head or a link in a link, are valid, and `normalize` fixes them. Reordering does not rely on arena allocation order matching tree order.

`NodeSyntax` preserves formatting needed for Markdown output without increasing the event or node size. Unmodified parsed syntax is inferred lazily from the original source extent. Explicit overrides live in a sparse map; `set_syntax(id, None)` disconnects inferred metadata. Item spread, link form and frontmatter fences remain separate from resolved semantic values. A reference's kind and label, and a footnote's label, are part of the event, beside the identifier (#192). Frontmatter's body accessor and first text edit exclude its fences. Replacement sections copied from another document materialize their values and metadata so that the other source can be dropped. A bound reference link or image copied from another document becomes an inline resource to where it led there, as the destination may have conflicting or no definitions of its label; an unbound one stays a name, bound by the destination's definitions, if any. Same-document moves and document cloning retain references.

The source stays immutable while ranges depend on it. Integer offsets survive moving or reallocating an unchanged buffer but do not track text insertions. Use AST edits for semantic changes, or reparse when replacing the original source.

## Serialization

The `serde` feature serializes the source, arena slots and sparse syntax overrides. Deserialization constructs the arena directly and validates the complete forest, including detached subtrees, before exposing it. Validation rejects invalid UTF-8 ranges, broken or cyclic links, duplicate ownership, illegal roots, invalid event values, children the content model does not hold and incompatible metadata. It does not collect a complete event stream as an intermediate representation.

Source ranges stay ranges. Literal and owned values share the serialized `Value` representation; deserialization owns those strings. Node IDs retain their indices within the restored document. This arena format replaces mdast JSON and is not the mdast interchange schema.

## Diagnostics

`Message` retains its role as the serializer error and custom producer diagnostic. Its `reason` is now `Cow<'static, str>` (`"literal".into()` or `format!("... {value}").into()`), while `source` and `rule_id` are static strings. Use `span: Some(start..end)` for a source byte range, or `span: None` for an option error. This replaces boxed strings and `place: Option<Box<Place>>`. `unist::{Point, Position}`, `message::Place`, and the hidden `Location` utility have been removed; document and event spans remain the location contract.
