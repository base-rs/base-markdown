# Document AST and migration

`Document<S>` is the single source-backed arena AST, constructed incrementally from semantic events and rendered through the same HTML writer as direct parsing. `S: AsRef<str>` can own or borrow a complete UTF-8 buffer. Ordinary text and attributes retain offsets; decoded constants and constructed values use literal or owned storage.

## Migrating from mdast

The legacy recursive AST, its compiler and separate HTML renderer have been removed. This deliberately changes the public API and serialized AST representation.

| Previous API | Document API |
| --- | --- |
| `to_mdast(source, options)` | `Document::parse(source, options)` |
| `Node` enum and child vectors | `DocumentNode::kind`, `NodeId`, `Document::children(id)` |
| `walk` | `Document::descendants(id)`, including the starting node |
| `text_content()` | `Document::text_content(id)` |
| `HtmlRenderer` and `render_with` | `Document::render_html`, `render_node`, or `render_events(document.source(), document.events(), ...)` |
| Custom `Renderer` | A consumer of semantic events, or a traversal of document node IDs |
| `Node::to_markdown`, `MarkdownRenderer` | `to_markdown(&document)`, `to_markdown_with_options`, or `to_markdown_node` |
| `Headings::extract` | `Document::headings(&HeadingOptions)` |
| `extract_children` / `Fragment` | `Document::extract_children(parent)` returns detached IDs in the same arena |
| Child-vector mutation | `append_child`, `detach`, and `attach(parent, child, before)` |
| Parsing Markdown into a node | `Document::parse_children(parent, markdown)` replaces the parent's children, read with the document's `parse_options` |
| `replace_heading_section` | `Document::replace_heading_section(parent, index, &replacement, replace_heading, remove_subsections)` |
| Code-fence helpers | `EventKind::CodeBlock::fence` and `NodeSyntax::Frontmatter` |

Events and AST nodes express resolved Markdown meaning. A reference is a name and a definition a binding of it: a document stores a reference link or image as `Target::Reference`, its kind and label, with no destination, and it leads where the first link reference definition of its label in document order does, as the parser matches labels; a footnote call likewise calls the first footnote definition with its identifier to end, which is the first in document order unless one is nested in another of its identifier, as the HTML renderer shows that one. Nothing stores a binding on a reference. A document keeps an index (`bindings::Index`) of every definition and footnote definition of the attached document by key, built from the definitions `AstBuilder` met, in the order they end, and on deserialization, and kept by every edit that attaches, detaches or relabels one (`set_kind`, `append_child`, `attach`, `detach`, `extract_children`, `replace_heading_section`, `insert_from`); it files each entry by a hash of its key, the canonical label or identifier, in groups of a few slots, with the keys in one string it owns, so it borrows nothing, and a key whose group is full goes to an overflow ordered by key, so filing or finding a key takes constant time usually and at most time logarithmic in the number of keys whatever the keys are: the hash has no random seed, which this `no_std` crate has no source of, so keys can be made to collide, and the bound rests on the overflow. An entry holds its binding first and the copies of it, the later definitions of the key, in order after it. Parsing, building and deserializing accept copies, as Markdown does, but no edit adds one: appending, attaching, relabelling or copying in a definition of a key the attached document already defines, a subtree that defines a key twice, or moving within the document a definition whose key has copies, is rejected with `StreamError::InvalidValue` before anything changes. Detaching a definition removes it from the index, so the only definition of a key can be detached and attached again, while a copy, once detached, cannot. So the order of a key's definitions never changes while they are attached, and removing the binding makes the next copy the binding with no comparison of positions. A lookup takes that time whatever copies there are, as an entry keeps its copies in a queue that gives up its first in constant time. `Document::definition`, `footnote_definition` and `destination` and the per-subtree operations (`subtree_events`, `text_content`, `render_node`, `to_markdown_node`) look the attached document up in the index, so each reference costs one lookup there whatever the node's depth, as the document keeps one bit per node saying whether it is attached (set when the document is built or normalized and flipped only for subtrees that move into or out of the attached document, so detaching nested containers one by one costs each its own blocks), and calling one per section takes time linear in what each covers; they look a detached tree up through a table of it (`bindings::Table`), built in one pass over its containers of blocks, which are all that can hold a definition, so a call on a node in a detached tree takes time linear in that tree, and calling one on each node of a large detached tree takes quadratic time, a known gap (#226), as caching the table would need interior mutability. `Document::bindings` builds such a table of the attached document. `normalize` removes each copy, as copies render nothing, and gives each place a copy leaves, or a definition hoisted out of one fills, the separators the parser puts there between the blocks then beside it, and the end of the document the ones it puts there once normalizing is done, so the output reads back as the tree, unless those already there could not be the parser's, as an edit leaves them, and it pins the spread of each item above a copy, which is otherwise read from the source between the item's blocks, where the copy's lines would count as blank, so a normalized tree defines each key once; a definition in a footnote definition that is a copy, which binds its own key, takes the copy's place, with what it holds, and the copies in that go in turn. It does so in one pass from the root in document order that rebuilds each child list that holds a copy, or that a definition leaves, once, so the result depends on the tree alone and takes time linear in the copies, the containers above them and their children, and what the copies hold, with scratch marks cleared only where they were set, so normalizing many trees that hold copies costs what they hold, not the arena once per tree. Everything else a copy holds goes with it, as other nodes `normalize` removes do: each node left in it becomes a detached root of empty text without children, which binds, refers to and holds nothing, so a removed copy is never a tree to normalize, look references up in or find copies in, and copies nested in copies to any depth cost what they hold. The root of a tree is never a copy, as its definitions are taken in the order they end but for the root, which comes first: a footnote definition detached from a copy of itself stays what it is and loses the copy it holds. The HTML changes in five cases, which [the contract](normalize-serialize.md), clause 3.4, states. A paragraph that a rule makes loose is likewise given the separator the parser puts after one, and a table that ends an item or footnote definition the one that a blank line after it in the item gives, which can change too when a rule makes the list loose or tight. `DocumentEvents` makes its lookup at the first reference or footnote call it meets, and gives each bound reference as `Target::Resolved`, with its definition's destination and title, so a parsed document's events, and its HTML, are the parser's; it handles references and footnote calls on a cold path, so other nodes take the path they took before. A document also records whether every reference and footnote call in it is known to be bound, which a parsed document is, as the parser gives a name only when a definition binds it, a built one is when its stream gave each reference resolved and bound and each footnote call its definition, and normalizing makes it; any edit of the tree clears it, and while it holds, `normalize` and `is_normalized` look nothing up for references. A stream carries resolved targets only: `render_events` rejects a `Target::Reference` with `StreamError::InvalidValue`. It renders footnote calls from the stream alone, so one without its definition fails with `StreamError::Unbalanced`, while `AstBuilder` keeps such a call, which the document then renders as its text. The parser's event stream carries `Target::Resolved` too; `AstBuilder` keeps its name only when its label binds to a definition with the same destination and title in the built document, and otherwise stores a resource to them, so that a resolved reference never loses its meaning, and `set_kind` and `append_child` store one as a resource, while deserialization rejects one with `StreamError::InvalidValue`. A reference or footnote call that no definition binds is valid but not normalized: `DocumentEvents` gives it as the text it reads back as, so rendering, `text_content`, `headings` and heading ids agree, and `normalize` makes it that text, as `insert_from` and `replace_heading_section` make one they copy. A detached subtree is its own tree, which binds only its own references. Being normalized is therefore a property of the whole document: removing or relabelling a definition can leave references elsewhere unbound. Images contain semantic alternative-text children. Tables have explicit head/body containers and per-cell alignment. A task item's checkbox is `Item { checked }`, and frontmatter is the root's `Tag::Document { frontmatter }`, so neither is a node. Soft breaks and output separators are explicit leaves. Parsed text forms one node per source slice: it is split only at backslash escapes and character references, whose values are not a slice of the source. `Document::normalize` joins adjacent text, removes empty text, merges adjacent emphasis, strong or strikethrough of the same kind, unwraps a link inside a link unless it is an autolink, and gives a table the parser's shape, in linear time; `Document::is_normalized` reports whether it would change anything. Normalize a parsed or edited tree before serializing it to Markdown. Direct-child indices, including the section helper's heading index, include separator nodes. Use IDs or filtered child traversal when source whitespace should not affect selection.

Source spans are half-open byte ranges, rather than legacy unist positions. Parsed ATX and setext heading spans include the terminating source line ending when present: use `node.span.end` directly to locate the heading body, without skipping another CR/LF. Frontmatter spans end at the closing fence before its terminating line ending. Value ranges identify semantic text and can differ from the enclosing node span; use `Text::resolve` and `Document::frontmatter` instead of slicing node spans for decoded values. Use `Document::destination` or `Bindings::destination` for where a reference leads, rather than searching definitions again: they honor first-definition precedence and the parser's label matching.

Markdown serialization preserves supported Markdown structure rather than every possible valid tree. For example, Markdown tables require a header: normalizing a table without its head makes its first row the header, and gives every row as many cells as the widest. Use HTML rendering to preserve such custom table structure.

## Ownership and editing

Node IDs are scoped to their document. Arena slots remain stable across edits and are not reclaimed on detachment. A detached subtree can be inspected, rendered, serialized or reattached. The arena holds parent/first-child/next-sibling links; traversal needs neither a heap stack nor cloned strings. Normalizing invalidates the IDs of the text and attention it joins into a preceding node; other IDs stay valid. Appending in document order, each node after the subtree before it is complete, takes amortized constant time per child: the last node appended leads to the parent's last child, and a list item's ending is refreshed from the appended child alone. Appending elsewhere scans the parent's children; inserting or moving children may scan sibling chains; editing avoids permanently enlarging every node with editing-only links or indices.

`text_mut` detaches a source-backed value on its first edit. `set_kind` changes semantic content while retaining provenance and structure, and clears authored-syntax inference for that node. Checked edits reject malformed values, cycles and invalid roots.

## Parsing into a node

`Document::parse_children(parent, markdown)` parses a fragment with the document's `parse_options` and replaces all of the parent's children with it; the old children are detached as `extract_children` leaves them. The parent decides the parse: one that holds phrasing (paragraph, heading, table cell, attention, link, image) takes one paragraph's content, and a fragment that parses into anything else, such as `# h`, `a\n\nb`, `- x`, a setext heading or a definition, is `StreamError::InvalidNesting`; an empty or blank fragment empties the parent. One that holds blocks (root, block quote, item, footnote definition) takes a document's blocks. A list, table, head, body or row is `InvalidNesting`, a leaf `Unbalanced`. A table cell's fragment is parsed as the only cell of a table, `| fragment |`, so it reads as written in a cell: `|` must be escaped, and one with a line ending, such as `a\nb`, is `InvalidNesting`, as a cell is one line of its row. A link's fragment, or one under a link, is parsed as link text, `[fragment]()`, so it keeps the spaces at its edges, a fragment that holds a link is `InvalidNesting`, as the parser reads no link in link text, and so is one whose brackets or trailing backslash would end the text early, such as `[a` or `a\`, as splicing it into the written link would change more than the link. The fragment is parsed as though it were not at the start of a document, so frontmatter is never read and the document's own is kept.

References and footnote calls in the fragment are names, as in a parsed document, and the parser reads one where a definition binds its label, in one parse: the parse is given the definitions outside the fragment through `definitions::Outside`, which `Definitions` asks, once for each key, whether a definition binds a key its own definitions do not define. `Around` answers from the document's index, `bindings::Index::binds`, for an attached parent, passing over the replaced children's definitions of the key, which no longer bind, and for a detached one from a table of its tree without them, built at the first question. A fragment that uses no label asks nothing. One that nothing binds stays text. Under a link, footnote definitions are not offered, so a call stays text and the content model's rule holds, as the parser leaves a link's brackets text where a call is inside them. As an edit adds no copy of a binding, a fragment parsed into the attached document whose definitions repeat a key, or have one that a definition outside the replaced children has, is `StreamError::InvalidValue` through the same `bindings::tree_keys` and `Index::admits` check as `replace_heading_section`, before anything changes, and `edit` restores `settled`; so the fragment's own definitions and those outside never both bind a key, and no order between them is needed. The fragment's definitions become ordinary nodes, indexed as they are copied into an attached parent. The parsed fragment is copied with `copy_subtree`, as for `replace_heading_section`, which owns its values and syntax and refreshes paragraph and item context, but without the fragment's bindings, so a parsed reference keeps its name, which binds here as the parser read it.

The copy adds no separator that writing the fragment in place would not, since the serializer writes the blank lines a separator stands for. In any parent but the root, the separators after the last block are dropped, as the parent's end ends them. In an item of a tight list, a separator after a paragraph is dropped unless a paragraph follows it, which normalizing then joins, as a tight item holds no two paragraphs in a row; the separator a hand-built item keeps after its last block is #216. An item's spread is read from the source between its blocks, which copies are not in, so the item is given the fragment's spread as syntax, or none in a tight list. The cost is the fragment, the replaced children and one question of the index for each label used, not the size of the document, in the attached document; `parsing_into_every_section_of_a_document_is_linear` and `parsing_deep_into_a_nest_is_linear` time it against controls. A detached parent has no index to ask, so the first label the fragment uses but does not define costs one pass over the parent's detached tree (`bindings::Table::without`), and editing each node of a large detached tree takes quadratic time, the gap of #226. Into a phrasing parent, whether a link or a cell is above decides how the fragment reads, and finding out walks the parent's phrasing ancestors to their block, in time linear in the depth of the phrasing nest, so many edits deep in one nest take quadratic time, as `append_child` of a footnote call or break and every `attach` do (#233, a per-node cache of what is above).

## Copying from another document

`Document::insert_from(parent, after, &source, nodes, &InsertOptions)` copies nodes of another document's attached tree, often its root's children, into `parent` after `after`, or first for `None`, and returns `Inserted { nodes, footnote_definitions }`, the copies of the selected nodes and of the footnote definitions they brought. `Document::heading_section_last(heading, subsections)` gives the last node of a heading's section, or the heading for an empty one, so "insert this document under that heading" is `insert_from(root, Some(document.heading_section_last(heading, true)?), &other, other.children(other.root()), &options)`. The position is the sibling to insert after, not before as for `attach`, as nodes have no previous-sibling links, so finding the sibling before a node scans the parent's children, which would make many inserts into one parent quadratic, and `heading_section_last` gives the node to insert after; `after` costs nothing to follow, and appending is `children(parent).last()`.

A copy renders as its original does in its own document, as for `parse_children` and the old `replace_heading_section`: a reference bound there becomes a resource to where it leads, and one that nothing binds there becomes its text, as `normalize` makes it, the text around its children, so one copy can be several children, all listed in `Inserted::nodes`, and the next copy goes after the last of them. So link reference definitions are never copied, wherever they are among the nodes, as nothing copied names them. Footnotes are names that have to travel: each footnote call that is bound there brings the footnote definition it calls, which is found through the source's index wherever it is, copied once whatever the number of calls, and the calls in a copied definition bring theirs in turn, with a work list, so a definition that calls itself or a cycle of them is copied once each. A footnote definition among the nodes that nothing copied calls is not copied. Definitions and footnote definitions are skipped at any depth of the copied content, and so are the separators they leave redundant in a child list. Into a container of blocks, the top-level copies get the separators the parser writes, between them and at both boundaries with the children beside them: one after each block that something follows, but none after a definition, which takes its place, none after a paragraph of an item of a tight list before a block other than a paragraph, and none after the last block of a container other than the root; a copied separator is reused where one is wanted, and a new one made otherwise. So two paragraphs in an item of a tight list stay two in the tree and in the HTML, `<li>a\nb</li>`; `to_markdown` before `normalize` writes that item loose, and `normalize` joins them with a soft break (contract 3.4 and 5.2), and `replace_heading_section` in an item writes what reads back. The copied footnote definitions go after the copies in `parent`, in the order they are first called, so a section copied under a heading keeps its notes with it and costs nothing to place; when `parent` cannot hold a footnote definition, as a paragraph, a list or other phrasing cannot, or is an item of a tight list, where one after a paragraph would be written after a blank line and make the list loose, they go after the nearest ancestor whose container can. In a root that holds phrasing, which nothing can be put after, the insert is rejected with `StreamError::InvalidNesting`.

A copied definition's identifier is taken when the tree that holds `parent` binds it (the attached document through its index, or a detached tree through a table built for the insert, #226), or has a call of it that nothing binds, which the copy would otherwise capture; such a definition clashes. Unbound calls are found by one walk of the tree, only when the target is not settled: a settled document has every reference and call bound, and `insert_from` keeps it settled, as its copies are bound or text and its copied definitions take no identifier a call names. In `replace_heading_section`, calls in the replaced section are not counted, and a call bound only by a definition the section held counts as bound, so the copy can take its identifier and the call calls it, as it called the definition replaced. `FootnotePolicy::Relabel`, the default, gives it a fresh identifier and rewrites its copied calls: the identifier and each label get the suffix `-j`, for a `j` from 2 such that the identifier is neither taken in the target nor one of the copied definitions' own, kept or already given, so `n` becomes `n-2`, and inserting it again `n-3`; it is deterministic, but not always the smallest free one, so with `x`, `x-2`, `x-3` and `x-5` taken it is `x-6`. The fresh suffix is found by galloping, `-2`, `-3`, `-5`, `-9` and so on, to a free one and searching back to the first free one after the taken ones, which is the first free one when the taken ones run from `-2` without a gap, as relabelling makes them, so relabelling the same note in many inserts costs a logarithmic number of lookups each, not a linear one. A label too long for a fresh suffix is rejected with `InvalidValue`. `FootnotePolicy::Reject` rejects any clash with `InvalidValue`, including an identifier only an unbound call names. "Merge identical" and "replace" are not offered: deciding identical needs a comparison of two subtrees across documents, and replacing moves or removes a binding the rest of the target uses. So a call in the target keeps calling what it called, or nothing.

`InsertOptions::heading_shift` is added to every copied heading's level, including those in copied footnote definitions, and a level outside 1 to 6 is rejected with `InvalidValue`, as `set_kind` rejects such a heading, not clamped, as a clamp would flatten levels that the copy meant to keep apart. The containment rule is the one content model: each copy against the parent, whose first child is its own or the first copy, and, when the parent is below a link or a table cell, every copied node against `Reach`, so a footnote call into a link and a break into a cell are `InvalidNesting`. A node that is not in the source's attached document, which its bindings do not cover, is `InvalidRange`. Into an item, the item's spread is pinned as syntax: spread when it was, or, unless the list is tight, when the copied blocks had a blank line between two of them in the source.

The insert plans first and changes nothing until every check has passed: the nesting and reach of every copied node, each shifted heading, the set of definitions and their identifiers, and the validity of each rewritten call and definition. It then copies each kept node once, with one lookup in the source's index for each reference and footnote call and one in the target's for each copied definition's identifier, marks the copies attached when the parent is, adds the copied definitions to the index, and refreshes the paragraphs around them and, into an item, the item from its last inserted ending child, as an append does, not all its children. So an insert takes time linear in the copied content plus those lookups; Many inserts of footnotes into one detached tree, or into an unsettled target, are quadratic, from the table and the walk. `many_inserts_are_linear`, `many_clashing_footnotes_are_linear` and `many_inserts_into_one_item_are_linear` time it against controls, and `random_inserts_render_as_their_sources` checks, after random inserts of random runs into random places, that the index binds as a fresh walk does, that normalizing reads back and is idempotent, that the copies render as their originals, but for footnote numbers and anchors, and that each container they go into renders as its children do, so no blocks fuse; its sources include each with its definitions detached, whose references and calls nothing binds.

`replace_heading_section` copies the replacement's root children with this machinery and the default options, with the replaced section's own definitions no longer binding, so a copied footnote definition may take an identifier only the section had. Before, it copied every definition and footnote definition of the replacement and rejected any that clashed with `InvalidValue`; now link definitions are not copied, footnote definitions are copied only when called, and a clash is relabelled.

## Content model

A tree is either valid or not built: one content model in `stream.rs`, `TagKind::holds`, decides which children each container holds, and every path that adds nodes checks it against the parent alone: `AstBuilder`, `EventHtmlRenderer`, `append_child`, `attach`, `replace_heading_section` and serde validation. `parse_children` inserts only what the parser built for a parent of the same content, under the same ancestors. The document root, block quotes, items and footnote definitions hold blocks and separators; paragraphs, headings, table cells, attention, links and images hold phrasing; a list holds items; a table holds heads and bodies, and they hold rows, with separators between them; a row holds cells. A root whose first child is phrasing holds only phrasing, an inline document, and one whose first child is a block holds no phrasing, so the two never share a parent. The rules on ancestors, `Reach` in `stream.rs`, are that a footnote reference cannot be inside a link and that no soft or hard break is inside a table cell, which is one line of its row (#214), nor inside a heading of level 3 to 6, or any heading without setext headings, as an ATX heading is one line (#257); the parser builds none, and `attach` checks them by scanning the moved subtree. A link inside a link is valid: the parser builds one for an angle autolink in link text, such as `[<http://a>](/b)`, as CommonMark does. A violation is `StreamError::InvalidNesting`; a heading level outside one through six is `StreamError::InvalidValue`. `render_node` renders a subtree in fragment mode, so its root's children need not fit a document.

`set_kind` changes a node in place only where its children and its place stay valid without a check: a container keeps its kind, except that emphasis, strong and strikethrough are interchangeable, and a leaf keeps its variant, with HTML staying a block or inline. Any other change creates a node, moves the children with `attach` and detaches the old one. Detaching or moving a subtree out always leaves a valid tree, if not a normalized one.

Validity is what can be built; being normalized is what is written exactly. Shapes that every tree passes through while being built, such as empty containers, rows of different widths, a table without a head or a link in a link, are valid, and `normalize` fixes them. Reordering does not rely on arena allocation order matching tree order.

`NodeSyntax` preserves formatting needed for Markdown output without increasing the event or node size. Unmodified parsed syntax is inferred lazily from the original source extent. Explicit overrides live in a sparse map; `set_syntax(id, None)` disconnects inferred metadata. Item spread, link form and frontmatter fences remain separate from resolved semantic values. A reference's kind and label, and a footnote's label, are part of the event, beside the identifier (#192). Frontmatter's body accessor and first text edit exclude its fences. Replacement sections copied from another document materialize their values and metadata so that the other source can be dropped. A bound reference link or image copied from another document becomes an inline resource to where it led there, as the destination may have conflicting or no definitions of its label; an unbound one stays a name, bound by the destination's definitions, if any. Same-document moves and document cloning retain references.

The source stays immutable while ranges depend on it. Integer offsets survive moving or reallocating an unchanged buffer but do not track text insertions. Use AST edits for semantic changes, or reparse when replacing the original source.

## Serialization

The `serde` feature serializes the source, arena slots and sparse syntax overrides. Deserialization constructs the arena directly and validates the complete forest, including detached subtrees, before exposing it. Validation rejects invalid UTF-8 ranges, broken or cyclic links, duplicate ownership, illegal roots, invalid event values, children the content model does not hold and incompatible metadata. It does not collect a complete event stream as an intermediate representation.

Source ranges stay ranges. Literal and owned values share the serialized `Value` representation; deserialization owns those strings. Node IDs retain their indices within the restored document. This arena format replaces mdast JSON and is not the mdast interchange schema.

## Diagnostics

`Message` retains its role as the serializer error and custom producer diagnostic. Its `reason` is now `Cow<'static, str>` (`"literal".into()` or `format!("... {value}").into()`), while `source` and `rule_id` are static strings. Use `span: Some(start..end)` for a source byte range, or `span: None` for an option error. This replaces boxed strings and `place: Option<Box<Place>>`. `unist::{Point, Position}`, `message::Place`, and the hidden `Location` utility have been removed; document and event spans remain the location contract.
