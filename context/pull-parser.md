# Pull Parser Architecture

The parser and document traversal produce the same pull-based semantic event stream. HTML rendering and AST construction consume that stream without first collecting it. This document describes the implementation; the existing mdast API remains available during migration.

```text
source + parser workspace → semantic events → HTML writer → output
                                           → AST builder → document
document traversal        → semantic events → the same HTML writer
```

## Contract

An event describes resolved Markdown meaning: a container opens or closes, text occurs, or a leaf such as a break occurs. It never exposes speculative delimiters, tokenizer states, or event-buffer edits. A producer implements `Iterator<Item = Result<Event, Error>>`; consumers pull only the events they need. Start events contain the metadata required to render their opening tags, including resolved destinations and list tightness. End events identify the container that closes. Events carry byte ranges for provenance independently of their semantic values. The root is a single document; container ends match their starts and cannot precede the opening source extent. Heading and footnote-definition capture cannot be nested within a heading or image alternative text. Consumers and checked AST edits enforce these constraints.

HTML rendering must satisfy this invariant with identical source and rendering options:

```text
render(parser.events()) == render(build_ast(parser.events()).events())
```

No component between producer and consumer collects the complete semantic stream. The AST builder accepts a mutable iterator and an event budget, preserving its open-node stack between calls. Exhausting a budget is different from reaching the end of the document. The HTML writer writes directly to caller-owned output storage. Stopping consumption is supported; producer preparation and already-completed work are not undone.

## Source storage and editing

A document owns a caller-supplied UTF-8 source buffer. A source-backed text value contains byte offsets, not pointers into the document's allocation. Moving or reallocating an otherwise unchanged source does not invalidate offsets. Source ownership is independent of the parser's lifetime; events themselves do not borrow parser scratch space.

Ordinary text and attributes retain source ranges. Literal replacements such as decoded entities and normalized line endings can use static strings; genuinely constructed values use owned strings. Raw source ranges and decoded semantic values are separate: escapes, entities, container prefixes, and code normalization prevent treating every value as one verbatim slice.

The AST uses a contiguous arena with stable node indices and parent/child/sibling links, rather than a separately allocated child vector for every node. Editing a source-backed value materializes that value into an owned string. The source remains immutable while dependent ranges exist. Replacing or editing the backing source requires reparsing or materializing dependent values first; integer offsets alone do not track insertions and deletions. A rope, piece table, incremental reparsing system, and shared ownership runtime are not prerequisites for this design.

## Preparation and bounded inline work

Pull-based event delivery is distinct from accepting input in chunks. The initial implementation accepts a complete UTF-8 buffer. CommonMark forward references and list tightness require preparation before some semantic events can be yielded. The block pass records source ranges, container relationships, and definitions. Inline parsing is deferred until its containing block is requested. Temporary delimiter and bracket state is bounded by the active inline region, and its storage is reused across regions.

The ordinary CommonMark and GFM block pass uses a compact arena of block relationships and source fragments. It recognizes paragraphs, headings, lists, quotes, rules, code, ordinary raw HTML blocks, GFM tables, and ordinary same-line reference definitions directly, without producing grammar enter/exit tokens or per-line edit vectors. Definitions retain authored order and source-backed labels, destinations, and titles; a separate sorted index selects the first definition for each normalized key. Duplicate definition events remain available to AST consumers. The lookup index is completed before event delivery, so forward references resolve normally. Inline resolution reuses one region's tokenizer storage and never splices inline tokens into the document-wide block buffer. The default HTML API uses the shared event writer; the old HTML token compiler has been removed.

Migration is incomplete. CommonMark HTML block types 1–6 use compact source fragments, including comments and raw tags; type 7/custom complete tags, NUL replacement, shared container tabs, single-line unclosed type 1–5 blocks at EOF, and unclosed HTML interrupted by container loss retain grammar preparation. GFM tables store container/cell records and source spans without allocating per-cell token vectors. Escaped table rows, partially consumed container tabs, lazy table headers that resume an explicit container prefix on the delimiter row, footnote definitions, and ambiguous definition/table boundaries retain grammar preparation. Other extension configurations and individually disabled core constructs still select the grammar compatibility producer.

Definition lookahead stops at the first physical line; multiline or malformed metadata, potentially oversized tab-expanded labels, possible next-line titles, setext continuations, arbitrary continuation indentation, lazy container continuations, and tabs in continued container prefixes conservatively retain grammar block preparation.

Ordinary inline text, escapes, entities, emphasis, same-line code spans, inline links, and reference links/images use compact candidates in reusable storage. GFM uses the same storage for strikethrough, ordinary task markers, and simple whitespace-delimited ASCII literal web/email links. Strikethrough shares bounded delimiter matching while retaining its run-length and single-tilde rules. Adjacent mixed emphasis/strikethrough runs retain grammar resolution to preserve partial-match precedence. Task markers with multiline or ambiguous whitespace retain grammar fallback. Literal links with paths, Unicode, punctuation ambiguity, or pending link/image labels retain the complete GFM grammar rules. The compact scanner preserves source-backed protocol destinations; adding `http://` or `mailto:` still constructs an owned destination. Multiline code/resources, inline HTML, and inline-code language metadata still select the grammar engine for their containing region. Ordinary leading inline links stay on the compact block path.

The compatibility block producer also uses compact inline resolution for eligible CommonMark and GFM regions without partially consumed tabs, so an unsupported block does not force unrelated paragraphs through the inline tokenizer. Full, collapsed, and shortcut references resolve against the prepared definition index. Multiline or malformed full-reference labels, labels spanning stripped source fragments, and tab expansion that might exceed the label limit retain grammar inline fallback. These paths must remain separately identified in performance measurements. The legacy mdast API also retains its own parser until semantic events cover its representation-specific metadata.

## Allocation and scanning budget

The target is no heap allocation merely to yield a start/end event or ordinary source text. Compact reference resolution reuses an ASCII normalization buffer and stores a definition index in each candidate. Compact definition preparation normalizes each authored label once and sorts/deduplicates indices once, avoiding repeated linear duplicate searches. Ordinary definition destinations and titles remain source ranges; constructed values still require cloning when opening links, and Unicode case normalization still allocates intermediate strings. Compact inline preparation selects the reference-free specialization when no definitions were collected. The compact producer selects CommonMark/GFM dispatch once at construction, and the CommonMark delimiter resolver maintains bounds only for its two active markers. Both inline producers share the prepared definition table; only an actual grammar inline fallback materializes its own list of normalized keys, once on first use. Unsupported definition forms and per-region grammar fallback remain measured migration costs. Parser nesting, delimiters, references, block records, AST nodes, and output need storage. Reuse vectors and caller-owned output, grow arenas geometrically, and avoid per-event boxes, trait objects, cloned strings, queues, or reference counts. A strict heap-free mode would need caller-provided capacity and explicit capacity exhaustion; it is not implied by this API.

Scan ordinary byte runs before invoking syntax handlers. Use byte-class tables for syntax candidates, indexed delimiter/bracket resolution, and batched source-to-output copies. SIMD is useful for finding candidate bytes and escaping HTML, not for replacing Markdown semantics. Prefer a small, portable scanner with a measured SIMD implementation and a tested scalar fallback. Keep architecture-specific unsafe code isolated, document its bounds and CPU requirements, and compare scalar and vector results at every boundary and alignment.

## Output compatibility

The default HTML API and arena traversal share one semantic interpretation. Opt-in heading IDs are generated from normalized semantic text, so multiline code and math spans no longer contribute whitespace that has already been removed from their visible value. For example, `` `\nb `\n--- `` produces `id="b"`, where the previous mdast-based heading capture produced `id="-b-"`. The legacy mdast API remains available with its existing representation.

Semantic end tags close their corresponding starts. The compact block producer makes mixed ordered/unordered lists following unclosed fences siblings, consumes container indentation tabs, and leaves empty unclosed code-fence bodies empty. These correct legacy hierarchy, tab, and synthetic-newline anomalies. The compatibility producer also corrects sibling-list hierarchy, while retaining the legacy tab and empty-code interpretation. Escaped emphasis delimiters are classified from their authored neighbors, correcting `\\**x**` to literal `*`, emphasized `x`, and literal `*`. Separators between sibling blocks retain their authored CR/LF/CRLF style. Separators inserted before closing container tags use the document’s first line-ending style; a mixed-ending input such as `x\n\n- # a\r\n ` therefore uses LF between `</h1>` and `</li>`, where the legacy grammar retained CRLF. This is an intentional formatting normalization; rendered structure is unchanged. Failed frontmatter lookahead also restores correct line positions instead of producing orphan quote closures. Retained HTML blank lines stop at their enclosing container boundary, preserving well-nested extension events. List resolution closes each individual item even when retained HTML leaves sibling items adjacent in the token buffer. Adjacent setext headings retain paragraph openings moved by earlier queued edits, preventing unbalanced compatibility streams. Reference-label normalization now preserves a collapsed space after the first word; labels such as `a b` and `ab` no longer collide.

Reference-bearing paragraphs now use the same compact emphasis resolver as ordinary paragraphs. This also corrects legacy delimiter-boundary cases: `[a]*a**_` with `[a]: /a` renders the link followed by `<em>a</em>*_`, where the grammar inline resolver left the emphasis literal. Output-preservation claims apply to the recorded corpus; these corrections outside it are intentional.

Ordinary definitions no longer force surrounding blocks onto the grammar path. These documents inherit the compact producer's container rules: trailing blank lines after a finished list do not loosen it, container indentation tabs are removed from code content, and contiguous indented code stays in one block. Definition events preserve their authored spans, including indentation and list-continuation tab provenance, while excluding the terminating line ending. Definitions remain invisible to HTML; list boundaries and terminal definition line endings do not introduce extra separators.

GFM now shares compact CommonMark block and inline rules outside extension constructs. This includes the list-tightness, code-line-ending, and emphasis corrections above. Incomplete fenced-code markers on lazy continuation lines remain in the paragraph. A blockquote containing `x`, followed by an unprefixed line containing two backticks, retains both lines inside its paragraph, matching CommonMark and Comrak. HTML source values preserve closing boundaries and authored line endings; unclosed HTML preserves context-sensitive terminal source endings through grammar fallback where needed.

Table boundaries deliberately retain the existing grammar's flow dispatch. Certain unindented rows beginning with `#`, `$`, backticks, `~`, `*`, `_`, `e`, `i`, or `{` bypass table recognition when their other block construct fails. Those candidates select grammar preparation even where other engines recognize a table. This optimization does not change that behavior. Table events retain alignment, header flags, and authored cell spans independently of trimmed inline content; missing cells have empty spans and surplus body cells remain ignored.

## Validation and performance acceptance

Validate parser → HTML and parser → AST → events → HTML against each other, the existing output corpus, CommonMark, GFM, extensions, edited documents, and malformed input. Test bounded AST construction, early drop, deeply nested input, source detachment, and writer failures. Preserve existing public APIs until their replacements cover the supported behavior.

Measure end-to-end rendering, event consumption, AST construction/traversal, allocation counts, and adversarial scaling separately. Use the pinned six-engine harness in `benches/comparison/`, report exact output agreement alongside timings, and retain raw samples and source revisions. Compare cold allocations and reused workspace/output separately. Do not claim the Inkmark target is met based on a subset fast path, different extension behavior, or a scanner-only microbenchmark.

The algorithmic references are pulldown-cmark's [two-pass pull design](https://pulldown-cmark.github.io/pulldown-cmark/dev/index.html) and [candidate-byte SIMD scanning](https://pulldown-cmark.github.io/pulldown-cmark/dev/performance.html). Any copied source must retain its license and identify its exact upstream revision; using these techniques does not require selecting another Markdown backend.

## Initial public API

`EventParser::new(source, options)` prepares compact block records or selects the documented compatibility producer. `render_events(source, events, compile_options, output)` pulls any producer through `EventHtmlRenderer`. `Document::parse(source_buffer, parse_options)` moves a caller-owned buffer into a source-backed AST, and `Document::events()` traverses it without allocating a traversal stack or cloning edited strings.

For bounded construction, retain an `AstBuilder` and call `consume(&mut events, event_budget)` until it returns `BuildProgress::Complete`. `Pending` means the budget was exhausted without probing for another event. Drop the parser before calling `finish(source_buffer)` to move the original buffer into the resulting document. `text_mut(node_id)` materializes only the edited value; node metadata can also be assigned through checked `set_kind`. Publicly supplied event streams and source ranges are checked. Direct Markdown-to-HTML rendering creates its parser from the renderer’s own source and uses that producer’s range and tag invariants instead of repeating range validation for every event; it retains the same renderer, balance checks, and safe string resolution. The checked parser → events → HTML and arena paths are compared with this internal path in regression testing.

## Borrowed implementation techniques

The block/container scanners and algorithms are adapted from `pulldown-cmark` 0.13.4, revision `38e4d08f14ec4bd9783270e9623db7681ebed968`, specifically `firstpass.rs` and `scanners.rs`. The copied scanners retain their MIT notice. Unlike that revision's first pass, this block pass records only source fragments for paragraphs and headings; it does not eagerly scan inline candidates throughout the document. It recognizes CR, LF, and CRLF, distinguishes Markdown indentation from VT/FF, and caches failed thematic-break lookahead using absolute offsets.

The inline producer indexes backtick runs by length once per source fragment, resolves emphasis using an opener stack and failed-search bounds, and invalidates nested link openers with a monotone boundary. Ordinary text, link destinations, code spans, and unchanged attributes remain source ranges; named character references use static decoded values. It prepares only the active inline block before yielding resolved events.

Candidate-byte scanning uses a two-nibble lookup table with AArch64 NEON when the target enables it, plus a portable scalar path. Inline text and HTML escaping share the scanner. Differential tests cover every input byte at every position around vector boundaries and multiple alignments; no vector load crosses the input slice. The default target remains portable and does not require runtime CPU detection.
