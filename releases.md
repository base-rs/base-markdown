# Releases

Earlier history, from before the package was renamed from `socketry-markdown`, is in [releases/socketry-markdown.md](releases/socketry-markdown.md).

## Unreleased

- Only form angle-bracket autolinks for the schemes in the link-scheme table, described in the next entry, and the email form `<user@host>`. This is a deliberate divergence from CommonMark, which accepts any scheme of 2–32 characters and an empty target, such as `<http:>`, so prose such as `Option<std::io::Error>` became a link to `std::io::Error`. Other `<scheme:…>` text is now raw HTML when it is valid HTML, such as `<xs:element>` with `html_tag_namespaces`, and text otherwise. Markdown serialization writes links with other schemes, such as `gopher://a`, as `[gopher://a](gopher://a)` instead of `<gopher://a>`, and writes `<…>` only when it parses back as the same link. Autolink text is now written without backslash escapes, which autolinks do not process, so `<http://a\b>` no longer gains a backslash on each serialization. In GFM table cells, links whose text contains `|` keep the `[text](url)` form, because a `|` in an autolink would split the cell.
- Use one table of link schemes for angle-bracket autolinks, GFM literal autolinks and the HTML renderer's safe `href` check, which previously disagreed. Each scheme has a kind that defines what must follow it: `http`, `https`, `ftp`, `sftp`, `ssh`, `irc` and `ircs` need `://` and a host, `mailto` and `xmpp` need an email address, and `tel` and `sms` need one or more of `+`, digits, `-`, `.`, `(` and `)` with at least one digit. Schemes match in any case. Angle-bracket autolinks now accept all of them, so `<irc://a.b>`, `<ssh://a.b>` and `<tel:+1-555-0100>` are links, while `<mailto:a>`, which has no `@`, and `<mailto:a@b.c,d@e.f>`, which has several addresses, are now text. An address may be followed by a `?query`, such as `<mailto:a@b.c?subject=x>`, and an `xmpp` address also by a `/resource`, such as `<xmpp:a@b.c/phone?message>`. GFM literals now also link `ftp://`, `sftp://`, `ssh://`, `irc://` and `ircs://`, but never `tel:` or `sms:`. Ending a literal at a backslash applies to every host scheme. With `html_tag_namespaces`, inline `<tel:1>` is now an autolink rather than a namespaced tag, though alone on a line it still starts an HTML block. The safe `href` list gains `ftp`, `sftp`, `ssh`, `tel` and `sms`; image `src` stays `http` and `https`. CommonMark example 596, `<irc://foo.bar:2233/baz>`, is a link again, as CommonMark expects.
- Escape `<` in text before characters other than letters, `!`, `/` and `?` when the rest of the same text forms an email autolink. Text such as `\<1@a.b>` was previously written as `<1@a.b>`, which parsed as an email link. Text such as `a <= b`, `<0.5%` and `-> Poll<T>` is still written unchanged.
- End GFM `www.`, `http://` and `https://` literal autolinks at a backslash, as email literals already did, because a backslash is never valid in a host name or URI and browsers read it as `/`. The text after it is parsed normally, so `www.com\_` links `www.com` followed by an escaped `_`, and a backslash hard break after a URL is no longer swallowed into the link. In GFM table cells, `www.a\|b` now links `www.a` followed by an escaped pipe. What precedes the backslash must still form a valid literal, so `www.\` is not a link. A backslash directly before an email address now blocks the email literal, as `/` does, so `x\a@b.c` and `http://x\a@b.c` no longer link `a@b.c`. This is a deliberate divergence from GitHub, which links `www.com\` as `http://www.com%5C`.
- The Markdown serializer no longer escapes text to keep it from becoming a GFM literal autolink, unlike `mdast-util-to-markdown` with `mdast-util-gfm-autolink-literal`. Text such as `www.example.com`, `https://a.b/c` and `a@b.co` is written as it is, so a GFM parser may link it. Escapes that only stopped a link from forming are dropped: `www\.example.com` is written as `www.example.com`, and `_` in an email domain such as `x@a_b.com` is no longer escaped.
- Record how a link that is not a reference was written as `NodeSyntax::Link { form: LinkForm }`, which is `Bare` for a GFM literal such as `www.example.com`, `Angle` for `<https://a.b>`, and `Explicit` for `[text](url)`. Parsed documents derive it from the source on lookup, copying a link keeps it, and `set_syntax` changes it. The Markdown serializer writes a link in its stored form and trusts it: a bare link is written as its text, unchecked, and a `<` just before it is escaped when `<text>` would read as an autolink. A link without a form, including one built by hand, is written as `[text](url)`, so a link whose text equals its destination is no longer written as `<…>` unless it was authored that way. Text after a bare link that the link would take is written in a form that ends it: a leading `&` as `&amp;`, and characters an email address would take with a backslash, or as a reference when they are alphanumeric. In a table cell, a `|` in a bare link is escaped. A bare link followed by text that needs a backslash escape, such as `www.com_` written as `www.com\_`, or by a backslash hard break, reads back with the backslash in the link for now; it will round-trip once the parser ends bare links at a backslash.
- Serialize text in linear time. Escape scans restarted from the start of the paragraph for every text node, so text such as long runs of `a_`, `$` or `[a\|b]` took tens of seconds to serialize at a few hundred kilobytes; they now take tens of milliseconds.
- Escape every backslash before ASCII punctuation, including one that follows another escaped backslash, as `mdast-util-to-markdown` does. Text such as `\\.` was written with one escape too few, so it rendered as `\.`.
- Write reference and definition labels with their backslashes as authored, since labels match by their raw text. Labels such as `a\*b` or `a\|b` gained backslashes on every serialization, and a reference in a table cell could stop matching its definition. Shortcut references such as `[a\*b]` now stay shortcuts.
- Escape a `)` or `.` after digits based on where the text sits in its line, not on how the parser split it into text nodes, and text right after an opening emphasis, strong or strikethrough marker no longer counts as the start of a line. `1)a` and `1\)a` previously swapped on every serialization, and `1\. a` was written as `1. a`, which parses as a list.
- Write whitespace at the start or end of emphasis, strong and strikethrough content as a character reference, wherever the text sits in its line, as `mdast-util-to-markdown` does. A letter directly outside such a marker is then written as a reference too, so the marker still opens or closes. `*&#x20;a*` was written as `* a*`, which parses as a list item, and `x *&#x20;a*` as `x * a*`, which is text.

## v0.1.4

- Give setext underlines, thematic breaks and other interrupting lines precedence over a following GFM delimiter row, as cmark-gfm does. Previously `a\n===\n|-` rendered the underline and delimiter row as a second paragraph instead of a heading followed by `|-`. After a link reference definition, an underline-shaped line followed by a delimiter row now forms a table header, and on a line that closes or opens containers it is a thematic break rather than paragraph text.
- Add `IncrementalParser`, which accepts Markdown in pieces and emits the events of each document-level block once appended text can no longer change it. Its combined output equals `EventParser` events without the document start and end events, except that references resolve only against definitions before the end of their document-level block.
- Escape Markdown syntax in GFM table cells as in paragraphs, as `mdast-util-to-markdown` does. Cell text such as `\_a\_` or `\*b\*` was previously written unescaped and re-parsed as emphasis.
- Escape pipes inside code and math in GFM table cells. GFM splits cells before parsing code, so an unescaped pipe in code split the cell, and usually stopped the table from parsing at all.

## v0.1.3

- Add `normalize_markdown` and `normalize_markdown_with_options`, which parse Markdown with GFM, frontmatter, and math and serialize it with default formatting and soft line breaks unwrapped. This is the normalization `bake-markdown` applies, so tools that generate Markdown can produce output it leaves unchanged.
- Add `ParseOptions::normalize`, the syntax `normalize_markdown` parses, so tools can inspect a document with the same structure the normalizer sees.
- Indent the content of GFM task list items to the list marker's content column rather than past the checkbox. Nested lists, paragraphs, and code in a task item were previously re-parsed as paragraph text or indented code, so repeated serialization changed or grew the document.
- Keep the blank line between a nested list and a following paragraph, table, definition, or setext heading in the same list item. Without it, the next parse continued the nested list's last paragraph, merging the two.
- Write a heading with soft line breaks as an ATX heading when soft breaks are unwrapped. It was previously written as a setext heading, which the next normalization turned into an ATX heading.
- Leave underscores between letters or digits unescaped when serializing Markdown, as `mdast-util-to-markdown` does, so `io_uring` and `snake_case` no longer become `io\_uring` and `snake\_case`. Such underscores cannot open or close emphasis, so the rendered output is unchanged.

## v0.1.2

- Replace a line ending before inline HTML only when the HTML could start an HTML block there, as `mdast-util-to-markdown` does. Line endings before other tags, such as `<span>` or `</span>`, are now kept, and a hard break before them is no longer lost.
- Keep a hard break before inline HTML that could start an HTML block by indenting the next line four spaces, so it continues the paragraph. Previously the break's line ending was replaced with a space, leaving a literal backslash.

## v0.1.1

- Keep inline HTML after text unchanged when serializing Markdown. Previously each serialization added a space before inline HTML in paragraphs, including those in block quotes and list items, so repeated normalization kept growing the gap. Only a line ending directly before inline HTML is now replaced with a space.
- Write every line ending in serialized Markdown as LF. CRLF and lone CR line endings inside code, HTML, math, front matter and titles were previously copied through, which left mixed line endings in otherwise LF output.
- Return inline subtrees from `to_markdown_node` without a trailing line ending, as cmark does. Text, emphasis, links, code and other phrasing content, including inline opaque nodes, serialize as `*b*` rather than `*b*\n`; non-empty documents and block subtrees still end with a line ending. This changes output for callers serializing inline fragments.

## v0.1.0

- Publish as `base-markdown` in the `base-rs` organization, with version numbering restarted at `0.1.0`. Releases require a `Release: vVERSION` Git trailer on the final release commit; version changes alone no longer trigger publication.
- Add a pull-based semantic event contract: `EventParser`, a direct HTML writer (`render_events`, `EventHtmlRenderer`), and an incremental `AstBuilder` that consumes events within a caller-supplied budget. The default HTML API and document traversal share the same writer. Ordinary source values retain byte ranges; editing a value detaches it into owned storage. Escaped punctuation and the following ordinary text now form a single text event and AST text node. Authored definition events, including duplicates, are kept in the event stream, while lookup uses a separate first-definition-wins index.
- Make the source-backed `Document` arena the sole AST, with checked subtree editing, heading and section helpers, lazy authored-syntax metadata (`NodeSyntax`), and validated arena serialization. Markdown serialization accepts documents or subtree IDs. Remove `mdast`, `to_mdast`, and the legacy `Renderer`, `HtmlRenderer`, and `MarkdownRenderer` APIs. This is a breaking API and serialized-AST format change; see the migration guide in `context/document.md`, which also covers heading spans, frontmatter values, and resolved reference destinations.
- Remove MDX support, including the `Constructs::mdx` and `ParseOptions::mdx` presets, MDX construct fields, parser callbacks and exports, hidden MDX identifier/source-map helpers, and JSX/expression/ESM AST variants. Braces and JavaScript import/export statements are ordinary Markdown; angle-bracket syntax follows CommonMark HTML rules. This is a breaking API change.
- Name individual extensions by their syntax: remove `gfm_` from construct flags and parser and HTML options. For example, `gfm_table` becomes `table` and `gfm_strikethrough_single_tilde` becomes `strikethrough_single_tilde`; serialized configuration keys drop the corresponding `gfm` prefix. The `gfm()` presets and extension behavior are unchanged. This is a breaking API and configuration-format rename; see `context/extensions.md` for migration examples.
- `EventParser::new` now returns the parser directly and `to_html_with_options` returns `String`; remove `?`, `.unwrap()` or `.expect(...)` from those calls. Checked event consumers, document validation and Markdown serialization retain their errors. This is a breaking API change; see the migration in `context/pull-parser.md`.
- Simplify diagnostics to borrowed or owned reasons, static identifiers, and byte spans, removing public unist coordinates and the hidden location utility.
- Remove the hidden public `decode_named` and `decode_numeric` compatibility helpers and their HTML 4 entity table. This is a breaking API removal; Markdown character-reference decoding continues to use HTML 5.
- Remove the no-op `log` feature; callers must stop requesting `features = ["log"]`. Remove the runtime `regex` dependency.
- Correct parsing: opt-in heading IDs use normalized semantic text, including multiline code and math spans; mixed-list closing tags balance against their semantic openings, correcting previously mismatched closures after unclosed fences; sibling lists after unclosed fences, container indentation tabs, and empty unclosed code bodies are handled correctly; failed multiline frontmatter attempts restore line positions; adjacent setext headings stay balanced when earlier underline text joins a paragraph; retained HTML blank lines stop at their enclosing container boundary, preserving sibling list items when HTML consumes the separating newline; emphasis adjacent to escaped delimiters, and cases such as `[a]*a**_` after a defined reference, resolve correctly; collapsed spaces stay significant in reference labels, so `[a b]` and `[ab]` resolve independently; multiline reference labels inside containers resolve, and tables are recognized after headers or rows beginning with syntax markers. Separators inserted before container closing tags use the document's line-ending style. GFM documents now share the CommonMark corrections for list tightness, literal code endings, emphasis boundaries, and incomplete fences in lazy paragraphs. Documents with same-line reference definitions now use the same container rules as plain CommonMark documents for list tightness, indentation tabs, and contiguous indented code.
- Correct Markdown serialization: an attached ordered item serialized on its own uses the correct marker, Unicode digits are no longer escaped as ordered-list markers, and Unicode lookalikes in URL schemes serialize as resource links rather than invalid autolinks.
- Improve parsing, rendering, and serialization throughput and large-document scaling, with fewer allocations and AArch64 NEON scanning for inline candidates and HTML escaping (with a portable scalar fallback). The convenience HTML API reserves up to 4 KiB of output capacity in advance. Rendered output, source spans, diagnostics, duplicate-definition precedence, first-call footnote numbering, expanded-tab label limits, stable node IDs, and edit-context hints are otherwise unchanged.
